# Phase 3: คำแนะนำภาษาไทยที่ลงมือทำได้

## สิ่งที่เพิ่ม

ผลวิเคราะห์ใหม่มี `actionable_recommendations` จากแม่แบบภาษาไทย 19 หัวข้อ: Phone 6, Camera 6 และ Laptop 7 หัวข้อ ไม่มีการเรียกโมเดลสร้างข้อความหรือ API ที่เสียเงินเพิ่ม และไม่ได้เปลี่ยนโมเดลจำแนกหมวด

แต่ละข้อมีสิ่งที่ตรวจพบ สิ่งที่เสนอ เงื่อนไขของสินค้า ขั้นตอน ตัวอย่างประโยค และเหตุผลที่เชื่อมกลับไปยังคลิปอ้างอิง ตัวอย่างประโยคเป็นแผนที่จะทดสอบ ไม่ใช่ผลทดสอบที่เกิดขึ้นแล้ว

ตัวอย่างหัวข้อความเร็วในการชาร์จ: เสนอให้ตรวจคู่มือ ใช้อุปกรณ์ที่รองรับ บันทึกระดับแบตเตอรี่ก่อนและหลัง และจับเวลาจริง ไม่บอกให้พูดคำว่า "ชาร์จเร็ว" บ่อยขึ้น และไม่แต่งกำลังไฟหรือเวลาที่ชาร์จได้

## ลำดับการทำงาน

1. ใช้หมวดที่ผ่านการตรวจรับจาก Active Model เท่านั้น ถ้า Unknown หรือถอดเสียงไม่ครบ จะงดข้อเสนอเฉพาะหมวด ไม่ใช้กฎทายหมวดทับ
2. ตรวจทุกหัวข้อในแม่แบบกับ Transcript ทั้งคลิป รวมคำพ้องและศัพท์ที่ตรวจแล้ว ข้อความปฏิเสธ เช่น "ไม่มีระบบกันสั่น" ยังนับว่าพูดเรื่องนั้นแล้ว จึงไม่แนะนำซ้ำ
3. ต้องพบเนื้อหาที่รู้จักอย่างน้อยหนึ่งหัวข้อเพื่อเชื่อมกับสิ่งที่ผู้ใช้พูด ตรวจบริบทที่เกี่ยวข้องเป็นอันดับแรก ถ้าไม่มี ใช้ได้เฉพาะบริบทรีวิวที่มีหลักฐานในข้อความ ไม่ใช้ชื่อไฟล์หรือชื่อคลิปมาเติมสิ่งที่ผู้ใช้พูด
4. ใช้เฉพาะ Transcript ของกลุ่มคลิปอ้างอิงผลตอบรับสูงที่ Pipeline คัดไว้ในหมวดเดียวกัน ไม่ใช้แถวสำหรับความยาวอย่างเดียว ไม่ใช้ Validation/Test หรือไอเดียจากชื่อเทรนด์
5. ตรวจ Video ID ไม่ซ้ำ มี Channel ID, URL, วันเผยแพร่, เวลาเก็บสถิติ และ Hash ของ Transcript ตรงกับข้อความที่เก็บ หัวข้อหนึ่งต้องมีอย่างน้อย 2 คลิปจาก 2 ช่อง เกณฑ์นี้เป็นการกันหลักฐานบางเกินไป ไม่ใช่การพิสูจน์นัยสำคัญทางสถิติ
6. เรียงตามความเกี่ยวข้อง ตามด้วยสัดส่วนคลิปที่พบหัวข้อนั้น จำนวนช่อง และค่าเฉลี่ย `log(1 + จำนวนครั้งที่พบในคลิป)` เพื่อไม่ให้การพูดซ้ำถี่ในคลิปเดียวครอบงำการเรียง แล้วเลือกไม่เกิน 3 ข้อ

ความเกี่ยวข้องมี 3 ระดับ: พบข้อความบริบทเฉพาะหัวข้อ = 2, พบการรีวิวและหัวข้อหลักในหมวด = 1, เชื่อมไม่ได้ = 0 ซึ่งระดับ 0 ไม่สร้างคำแนะนำ คะแนนนี้เป็นกฎจัดลำดับ ไม่ใช่ความน่าจะเป็นหรือคะแนนคุณภาพคลิป

ระบบตรวจครบทุกหัวข้อก่อนจำกัดจำนวนที่แสดง มี 1 ข้อก็แสดง 1 ข้อ ไม่มีหลักฐานก็ไม่เติมให้ครบ 3 และไม่ได้จำกัดการสกัดคำสำคัญไว้ 3 คำ

## หลักฐานและการบันทึก

- `evidence_bundle.action_topics` เก็บผลตรวจทุกหัวข้อ คำพ้อง ข้อความอ้างอิง ตำแหน่งข้อความ และ Timestamp เฉพาะเมื่อมีต้นทางจริง
- `actionable_recommendations.assessments` บอกเหตุผลรับหรือไม่รับแต่ละหัวข้อ พร้อมค่าที่ใช้เรียง
- แต่ละข้อเชื่อม `evidence_topic_id` ไปยัง Dataset row IDs และเอกสารอ้างอิงที่แช่แข็งไว้ใน Phase 2 เปิดอ่านข้อความ สถิติ และเวลาเก็บได้จากปุ่ม "ดูข้อความและคลิปอ้างอิง"
- บันทึกวิธี `thai-action-advice-v1`, แม่แบบ `thai-action-templates-v1`, SHA-256 ของแม่แบบ และ Fingerprint ข้อมูลพร้อมผลวิเคราะห์ใน `analysis_results.summary` ใช้โครงสร้างบันทึกเดิม ไม่เพิ่มตาราง
- การเปิดผลที่บันทึกไว้ไม่สร้างข้อความใหม่ตามแม่แบบหรือ Dataset รุ่นล่าสุด ผลเก่าที่ไม่มีข้อมูล Phase 3 ยังแสดงรูปแบบเดิม หากต้องการคำแนะนำใหม่ให้วิเคราะห์ใหม่
- ผลใหม่ใช้ข้อเสนอแบบลงมือทำแทนรายการคำดิบในส่วนคำแนะนำ ส่วนความยาวคลิปและไอเดียจากกระแสยังแยกตามเดิม

## ข้อจำกัดที่ต้องอธิบายตรง ๆ

- การจับคำพ้องยังเป็นชุดคำที่ตรวจแล้ว ไม่ใช่ความเข้าใจภาษาทุกรูปแบบ ถ้าถอดเสียงผิดหรือใช้คำที่ยังไม่รู้จัก อาจพลาดการตรวจพบได้ จึงใช้คำว่า "ยังไม่ตรวจพบในข้อความที่วิเคราะห์" ไม่ยืนยันว่าผู้ใช้ไม่เคยพูด
- ยังไม่มีฐานสเปกรายรุ่น ทุกข้อจึงมีเงื่อนไขก่อนทำ ไม่สมมุติว่ามีชาร์จไร้สาย กันสั่น ตรวจจับดวงตา พอร์ตแบบพิเศษ หรือเพิ่ม RAM ได้
- คลิปอ้างอิงมีผลตอบรับตามเกณฑ์คัดเลือกของระบบ แต่ไม่ได้พิสูจน์ว่าหัวข้อนั้นเป็นสาเหตุของยอดวิว/ไลก์/ความคิดเห็น การเพิ่มหัวข้อไม่รับประกัน Engagement
- การทดสอบอัตโนมัติและภาพ Browser ใช้ข้อมูลจำลองที่ระบุชัด ไม่ใช่ผลประเมินคุณภาพคำแนะนำจากผู้ใช้จริง และไม่ใช่การวัดความแม่นของโมเดลจำแนก

## ไฟล์และการตรวจ

- `app/services/recommendation_templates.json`: เนื้อหาและคำพ้องแต่ละแม่แบบ
- `app/services/actionable_recommendations.py`: ตรวจคำซ้ำ ความเกี่ยวข้อง หลักฐาน และเรียงข้อเสนอ
- `app/services/recommendation.py`: เรียกหลังสร้าง Evidence Bundle
- `frontend_flutter/lib/widgets/actionable_advice_panel.dart`: แสดงข้อเสนอและเปิดหลักฐาน
- `tests/test_actionable_recommendations.py`: ทดสอบสามหมวด การงดแนะนำ การไม่ซ้ำ การเรียง และผลที่บันทึกไว้
- `frontend_flutter/test/actionable_advice_test.dart`: ทดสอบ UI ข้อมูลว่าง ผลเก่า และเปิดหลักฐาน
- `scripts/browser/verify_actionable_advice.cjs`: ตรวจ Browser ที่ความกว้าง 1,000/1,440 พิกเซล โดยไม่เขียนผลวิเคราะห์หรือ Dataset ลงฐานจริง
