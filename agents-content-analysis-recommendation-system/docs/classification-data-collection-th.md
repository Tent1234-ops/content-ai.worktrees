# แผนเก็บ Transcript เพื่อแก้ปัญหาผิดหมวด

ตรวจฐานข้อมูลวันที่ 27 กันยายน 2026 ตัวเลขด้านล่างนับเฉพาะรายการที่ผ่านเงื่อนไขใช้กับโมเดล ไม่ใช่ทุกแถวใน `dataset_contents`

อัปเดต 28 กันยายน: นำเข้าไฟล์ชุดใหม่ 85 รายการเป็นรอตรวจแล้ว ยังไม่รวมในตัวเลขที่ใช้ฝึกด้านล่าง
ดู [ผลตรวจไฟล์ใหม่และรายการซ้ำ](notebooklm-import-20260928-th.md) ก่อนเก็บเพิ่มหรือนำเข้าซ้ำ

## ต้องเพิ่มเท่าไร

ยังจำแนกเพียง 3 หมวดเดิม: Phone, Camera และ Laptop ส่วน Unknown หมายถึงนอกขอบเขต ไม่ใช่การเพิ่มระบบแนะนำสำหรับหูฟัง เมาส์ หรือคีย์บอร์ด

| กลุ่ม | ใช้ได้จริงขณะตรวจ | เป้าขั้นต่ำตามหน้า Admin | ต้องเพิ่มอย่างน้อย |
| --- | ---: | ---: | ---: |
| Phone | 50 | 80 | 30 |
| Camera | 52 | 80 | 28 |
| Laptop | 52 | 80 | 28 |
| Unknown สำหรับเลือกเกณฑ์ (Validation) | 0 | 10 | 10 |
| Unknown สำหรับทดสอบ (Test) | 0 | 30 | 30 |
| รวมที่เพิ่ม | | | 126 |

80 ต่อหมวดคือยอดรวม Train + Validation + Test ไม่ใช่ฝึก 80 แล้วเพิ่ม Test อีกต่างหาก
ข้อมูลฝึกจริงปัจจุบันมี Phone 39, Camera 39, Laptop 38; ที่เหลือเป็น Validation/Test
ตัวเลข 126 เป็นขั้นต่ำด้านจำนวน อาจต้องเก็บเพิ่มเมื่อคุณภาพไม่ผ่าน ช่องซ้ำ หรือข้อมูลไปอยู่คนละชุดกับที่ยังขาด

**ครบจำนวนไม่รับประกันว่าจะทายถูก 80% หรือเปิดใช้โมเดลได้** ต้องผ่านผลประเมินจริงทั้งสามหมวดและ Unknown แยกกัน
จำนวนนี้เป็นเกณฑ์ดำเนินงานของโปรเจค ไม่ใช่สูตรสากลหรือผลคำนวณขนาดตัวอย่างทางสถิติ

## เริ่มเก็บอะไรก่อน

เริ่มจาก Unknown เพราะตอนนี้ไม่มีตัวอย่างที่ผ่านเงื่อนไขเลย จากนั้นเน้น Laptop ที่สับสนกับ Phone gaming และกรณีกล้องมือถือกับกล้องจริง
ไม่ต้องให้ทุกคลิปยอดวิวสูง การฝึกจำแนกหมวดต้องการคำพูดที่หลากหลายและป้ายหมวดถูกต้อง

ตัวอย่างการกระจาย Unknown 40 คลิปด้านล่างเป็นแผนแนะนำ ไม่ใช่ระบบอนุมัติอัตโนมัติจากชื่อไฟล์:

| ลักษณะเนื้อหา | Validation | Test | รวม |
| --- | ---: | ---: | ---: |
| รีวิวคีย์บอร์ด | 3 | 7 | 10 |
| รีวิวเมาส์ | 3 | 7 | 10 |
| รีวิวหูฟัง | 2 | 8 | 10 |
| อุปกรณ์เสริมอื่นและเนื้อหาที่ไม่ใช่สามหมวด | 2 | 8 | 10 |

Unknown แต่ละชุดต้องมาจากอย่างน้อย 3 ช่อง และไม่มีช่องข้าม Train/Validation/Test แม้อยู่คนละหมวด
พยายามให้หลากหลายมากกว่าขั้นต่ำ และมีทั้งคลิปที่แยกง่ายกับคลิปเทคนิคที่ใช้ศัพท์คล้าย Phone/Laptop
กรณีคลิปพูดหลายผลิตภัณฑ์ให้คนตรวจตามเนื้อหาจริง อย่าดูจากคำเดียวหรือชื่อคลิปแล้วตั้งเป็น Unknown อัตโนมัติ

สำหรับสามหมวดเดิม แนะนำกันคลิปใหม่หมวดละ 10 คลิปเป็น Test **ภายในจำนวนที่เพิ่มในตาราง**
ที่เหลือเติม Train/Validation โดยเน้นกรณีสับสนง่าย จำนวน 10 เป็นชุดทดสอบเริ่มต้น ไม่ใช่หลักฐานว่าความแม่นน่าเชื่อถือสูงแล้ว
คลิป Test ใหม่ต้องไม่เคยใช้ปรับกฎ/เกณฑ์หรือเป็นคลิปอ้างอิง การมี `data_split=test` อย่างเดียวไม่พิสูจน์ว่าเป็น Test ใหม่
เก็บคลิปถ่ายเองไว้ทดสอบเส้นทางอัปโหลดและถอดเสียงด้วย โดยแยกจากชุด Transcript ที่ใช้ประเมินตัวจำแนก

## ทำไมเคยบอก Unknown 20 แต่ตอนนี้ 40

- ระบบเลือกเกณฑ์ Unknown ขั้นต่ำต้องการ Validation 10 และ Test 10 รวม 20 เพื่อทดลองวิธีตรวจรับ
- หน้า Admin ใช้เกณฑ์เปิดโมเดลที่เข้มกว่าอยู่แล้ว: Test Unknown 30 จึงต้องมี Validation 10 แยกต่างหาก รวม 40
- Unknown ที่ระบบจัดไว้ใน Train ยังไม่ใช้ฝึกเป็นหมวดที่สี่ และไม่เอามารวมยอด Validation/Test
- ไม่ย้าย Test ไปเป็น Validation เพื่อให้จำนวนครบ และไม่ลดเกณฑ์หลังเห็นคะแนน Test

## ขั้นตอนเก็บข้อมูล

1. หน้า Admin Train AI ดูหัวข้อ **แผนเก็บข้อมูลเพิ่ม** เพื่อดูยอดที่ยังขาดจาก Database ล่าสุด
2. ก่อนทำ Transcript ใช้ **ตรวจชุดข้อมูลจากรหัสช่อง** โดยใช้ `channelId` ที่ขึ้นต้นด้วย UC ยาว 24 ตัวจาก Metadata ไม่ใช่ชื่อช่องหรือ `@handle`
3. ระบบแสดงชุดที่จะได้รับตามกฎเดิมของช่อง ถ้าต้องเติม Unknown Validation/Test แต่ช่องได้ Train ให้หาช่องอื่น ไม่แก้รหัสช่องหรือบังคับย้ายชุด
4. ทำ Transcript จากคำพูดจริง ไม่ใช่ข้อความสรุปหรือข้อความแต่ง พร้อม URL ต้นทาง ความยาว และข้อมูลแหล่งที่มา
5. นำเข้าทาง Transcript Import เลือกสามหมวดตามจริง หรือ `Unknown/Other` สำหรับคลิปนอกขอบเขต
6. ตรวจใน Dataset Review แล้ว Approve พร้อมหมายเหตุว่าเป็นหูฟัง/เมาส์/คีย์บอร์ด/กรณีสับสนชนิดใด
7. กลับมาดูแผนเก็บข้อมูลอีกครั้ง เมื่อจำนวน คุณภาพ และการแบ่งชุดพร้อม จึง Train/ประเมิน และพิจารณา Activate โดยไม่เปิดใช้ให้อัตโนมัติ

การตรวจรหัสช่องไม่เรียก YouTube API ไม่เปลี่ยน Database และไม่ยืนยันว่าช่องมีอยู่จริงหรือคลิปเป็น Test ใหม่
หากข้อมูลเดิมของช่องอยู่คนละชุดกับกฎ จะขึ้นคำเตือนให้ตรวจ ไม่ย้ายข้อมูลให้เงียบ ๆ
ผลถอดเสียงและคำทายผิดเดิม 4 คลิปยังเป็นชุดตรวจซ้ำ ไม่ใช่ Test ใหม่

## โค้ดที่เตรียมไว้

- `app/services/classification_collection_plan.py`: คำนวณยอดขาดและตรวจชุดข้อมูลจากช่อง
- `app/services/classification_acceptance.py`: เลือกเกณฑ์ปฏิเสธจาก Validation แล้วใช้เกณฑ์เดิมกับ Test
- `app/services/classification_training.py`: แยก Train/Validation/Test และตรวจการรั่วของข้อมูล
- `frontend_flutter/lib/widgets/training_collection_panel.dart`: แสดงแผนและผลตรวจช่องในหน้า Admin เดิม
- `scripts/plan_classification_collection.py`: ดูแผนผ่าน Terminal แบบอ่านอย่างเดียว

```powershell
python -B -X utf8 scripts/plan_classification_collection.py
python -B -X utf8 scripts/plan_classification_collection.py --help
```

คำสั่งเหล่านี้ไม่ Train ไม่ Activate และไม่สร้างข้อมูลฝึกปลอม ถ้าใช้ `--output` จะเขียนเฉพาะไฟล์ JSON ใหม่และไม่เขียนทับไฟล์เก่า
ยังคงพักคำแนะนำเฉพาะหมวดจาก Active Model เดิมจนกว่าจะมีโมเดลที่ผ่านเกณฑ์หรือมีการเปลี่ยนโหมดอย่างชัดเจน

หลักการแยก Test ออกจากการปรับโมเดลอ้างอิง [scikit-learn: Data leakage](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)
ส่วนจำนวนตัวอย่างข้างต้นเป็นแผนของโปรเจคนี้ ไม่ใช่จำนวนที่เอกสารกำหนด
