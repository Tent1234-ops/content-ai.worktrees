# Phase 4: แสดงผลและบันทึกแผนปรับคลิป

## ผู้ใช้ทำอะไรได้

- อ่านสรุปหัวข้อที่ตรวจพบจากผลวิเคราะห์เดิมและคำแนะนำหลักก่อน สรุปนี้ไม่ได้สร้างเรื่องใหม่จากชื่อไฟล์
- เปิดดู Keyword, Transcript, หลักฐาน และเวอร์ชันเพิ่มเติมได้ ข้อมูลเหล่านี้ไม่ได้ถูกลบทิ้ง
- คัดลอกประโยคตัวอย่าง มีผลสำเร็จหรือล้มเหลวตาม Clipboard จริง
- เลือกคำแนะนำเพื่อนำไปปรับ เขียนรายละเอียดแผน และกดบันทึก เมื่อเลือกหรือพิมพ์จะเป็นฉบับร่างก่อน ไม่ได้บันทึกอัตโนมัติ
- เปิดจากรายการไอเดียของฉันกลับมาดูหรือแก้แผนเดิมได้ ยกเลิกการเลือกได้โดยบันทึกใหม่
- การเลือกไม่ใช่การยืนยันว่าปรับคลิปเสร็จ ตารางไม่มีสถานะ completed และ API ไม่รับฟิลด์นี้

## ข้อมูลเก็บที่ไหน

คำแนะนำ ข้อความอ้างอิง สถิติ เวลา และเวอร์ชันยังเก็บใน `analysis_results.summary` เช่น Phase 2/3 ไม่คำนวณใหม่เมื่อเปิดผล

เพิ่มตาราง `clip_revision_plans` ซึ่งสร้างผ่าน `Base.metadata.create_all` ตามวิธีเริ่มระบบเดิม จึงไม่ต้องแก้หรือลบคอลัมน์เก่า:

| ฟิลด์ | ความหมาย |
| --- | --- |
| analysis_id | Primary key และ Foreign key ไปยังผลวิเคราะห์ที่แผนนี้ใช้ |
| recommendation_fingerprint | SHA-256 ของคำแนะนำทั้งชุด รวมหลักฐานและเวอร์ชันที่บันทึกไว้ |
| selected_advice_ids | รหัสคำแนะนำที่เลือกจากผลนั้น ไม่รับข้อความคำแนะนำที่ส่งขึ้นมาแทนเอง |
| notes | รายละเอียดแผนจากผู้ใช้ สูงสุด 4,000 ตัวอักษร |
| revision | รุ่นของแผน สำหรับป้องกันหลายแท็บบันทึกทับกัน |
| created_at / updated_at | เวลาเริ่มและแก้แผนล่าสุด เก็บ UTC |

เป็นแผนล่าสุดหนึ่งฉบับต่อผลวิเคราะห์ ไม่ใช่ระบบประวัติทุกเวอร์ชันของบันทึกผู้ใช้ การแก้แผนไม่แตะข้อความผลวิเคราะห์ ถ้าพบว่าต้นฉบับเปลี่ยนจน Hash ไม่ตรง จะหยุดและแจ้งข้อผิดพลาด ไม่แทนด้วยหลักฐานใหม่

## API และการบันทึก

`GET /contents/{content_id}/revision-plan` อ่านแผนของเจ้าของผลเท่านั้น ถ้ายังไม่เคยบันทึกจะได้ revision 0 ไม่มีการสร้างแถวจากการเปิดอ่าน

`PUT /contents/{content_id}/revision-plan` ส่ง analysis_id, recommendation_fingerprint, expected_revision, selected_advice_ids และ notes

- ตรวจสิทธิ์เจ้าของผลก่อน และตรวจว่ารหัสที่เลือกอยู่ในคำแนะนำที่พร้อมใช้ของผลนี้
- ใช้ revision และ Hash ตรวจการบันทึกชนกัน ถ้าอีกแท็บบันทึกก่อนจะตอบ 409 โดยไม่ทับข้อมูลเงียบ ๆ
- บันทึกแผนและ Log `clip_revision_plan_save` ใน Transaction เดียว ตอบสำเร็จหลัง commit เท่านั้น
- หน้าเว็บตรวจเนื้อหาคำตอบด้วย ไม่ถือว่า HTTP 200 ที่ไม่มีข้อมูลยืนยันแผนคือบันทึกสำเร็จ
- ถ้าบันทึกล้มเหลว ฉบับร่างยังอยู่ให้ลองใหม่หรือโหลดแผนที่บันทึกเพื่อเปรียบเทียบ ขณะบันทึกจะปิดการแก้ไขและกันการกดซ้ำ
- ปุ่มออกจากผล/โหลดใหม่และการย้อนหน้าภายในผลมีการเตือนเมื่อแผนยังไม่บันทึก ฉบับร่างไม่ได้รับประกันว่าจะอยู่หลังรีเฟรช Browser หรือปิดแท็บ ต้องกดบันทึกก่อน

## ผลเก่าและข้อมูลไม่พร้อม

ผลเก่าที่มีคำแนะนำบันทึกไว้แสดงข้อมูลเดิม ไม่ใช้ Dataset ปัจจุบันมาเปลี่ยนข้อความ หากไม่มี Snapshot ครบ จะอ่านเฉพาะคำแนะนำจากตาราง `recommendations` เดิม พร้อมสถานะ `historical_legacy_no_snapshot` ไม่ฝึกโมเดลหรือสร้างคำแนะนำใหม่ตอนเปิดหน้า

ค่าความยาวเก่าที่มีเพียงเลขเดียวยังคงไว้เป็น historical_seconds แต่ไม่อ้างเป็นช่วงความยาวที่มีหลักฐานเพียงพอ สามารถวิเคราะห์ใหม่เป็นอีกผลหนึ่งเพื่อรับรูปแบบ Phase 3 ได้

Unknown, ข้อความถอดเสียงไม่สมบูรณ์, หลักฐานไม่เพียงพอ และไม่มีหัวข้อเพิ่มเติมที่รองรับ มีสถานะแยกกัน ไม่มีการเติมคำแนะนำให้ครบจำนวน และผลที่ไม่มีคำแนะนำยังเขียนบันทึกแผนส่วนตัวได้เมื่อมีผลวิเคราะห์ที่บันทึกแล้ว

## ทดสอบ

- `tests/test_clip_revision_plans.py`: บันทึก/แก้/ยกเลิกเลือก, เปิด SQLite จาก Connection ใหม่, สิทธิ์เจ้าของ, ข้อมูลจากอีกแท็บ, commit ล้มเหลว, ต้นฉบับถูกเปลี่ยน, ผลเก่า และ Cascade เมื่อลบผล
- `frontend_flutter/test/clip_revision_planner_test.dart`: ฉบับร่าง, การรอคำตอบก่อนแจ้งสำเร็จ, คงฉบับร่างเมื่อผิดพลาด, เปิดกลับ, Clipboard และการพับรายละเอียด
- `scripts/browser/verify_clip_revision_plan.cjs`: Browser ส่ง GET/PUT ผ่าน Route ของจริงไปยัง SQLite ชั่วคราวที่แยกจากฐานผู้ใช้ ไม่สร้างแผนทดสอบใน MySQL จริง

ส่วนแสดงผลไม่ได้พิสูจน์ว่าคำแนะนำช่วยเพิ่ม Engagement การบันทึกและการคัดลอกก็ไม่ใช่หลักฐานว่าผู้ใช้ปรับคลิปแล้ว
