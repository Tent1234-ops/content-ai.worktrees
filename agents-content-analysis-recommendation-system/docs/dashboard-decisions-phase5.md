## สูตรพร้อมตัวอย่าง

**อันดับ:** อันดับก่อน - อันดับหลัง เช่น #10 เป็น #4 = ขยับขึ้น 6 อันดับ เทียบเฉพาะแพลตฟอร์ม ประเทศ และขอบเขตเดียวกัน เช่น อันดับรวมไทยกับอันดับรวมไทย หรือหมวดเกมกับหมวดเกม

**ยอดวิวเพิ่ม:** ยอดปลายช่วง - ยอดต้นช่วง เช่น 1,300 - 1,000 = เพิ่ม 300 ครั้งใน 30 นาที

**ความเร็วเฉลี่ย:** ยอดเพิ่ม / เวลาที่ผ่านไปเป็นชั่วโมง ตัวอย่างข้างต้น = 300 / 0.5 = 600 ครั้งต่อชั่วโมง กราฟใช้อัตรานี้เพราะช่วงที่เก็บข้อมูลอาจยาวไม่เท่ากัน ไม่ได้ทำนายว่าชั่วโมงหน้าจะเพิ่ม 600 ครั้ง

**สัดส่วนหมวด:** จำนวนคลิปหมวดที่เลือก / จำนวนรายการอันดับรวมที่เก็บได้จริง x 100 เช่น เกม 12 จาก 40 รายการ = 30% ตัวหารไม่จำเป็นต้องเป็น 50 และห้ามนำจำนวนคลิปที่ขอหมวดละ 50 มารวมคำนวณ กราฟนี้ไม่ใช่ส่วนแบ่งผู้ชม YouTube

ยอดวิวสะสมแสดงแยกจากยอดเพิ่ม คลิปที่มียอดสะสมมากจึงไม่ถูกเรียกว่ากำลังโตเร็วโดยอัตโนมัติ

## เมื่อข้อมูลไม่ครบ

- ช่องว่างเกิน 90 นาที หรือมีรอบเก็บไม่สำเร็จ/ข้อมูล mock คั่นอยู่: ตัดเส้นอันดับและสัดส่วน ไม่คำนวณยอดเพิ่มข้ามช่องว่าง
- ไม่พบคลิปในรอบที่เก็บสำเร็จ: ไม่ใส่อันดับ 0 หรือ 51 ไม่ใส่ยอดวิวศูนย์ และไม่สรุปว่าคลิปถูกลบหรือหมดความนิยม
- กลับมาพบคลิปหลังจากหายไป: ต้องมีค่าของคลิปในสองรอบติดกันที่เปรียบเทียบได้ก่อน จึงคำนวณยอดเพิ่ม
- ยอดวิวหายไป/ไม่ทราบนิยามตัวนับ/นิยามเปลี่ยน: ไม่คำนวณยอดเพิ่ม
- ยอดสะสมถูกปรับลด: แสดงสถานะว่าตัวนับลดลง ไม่ใช้เป็นความนิยมติดลบ
- ยอดเดิมเท่ากันและมีหลักฐานสองรอบครบ: ยอดเพิ่ม 0 เป็นค่าจริง จึงแสดงได้
- ได้ผลลัพธ์ว่างจริง: เก็บเป็นรอบสำเร็จที่ไม่มีรายการ แต่ไม่คำนวณเปอร์เซ็นต์จากตัวหาร 0
- รอบล่าสุดล้มเหลวหรือข้อมูลเก่า: แสดงคำเตือนและไม่กล่าวว่าอันดับกำลังขยับในตอนนี้

ตัวเลือก 24 ชั่วโมง, 5, 7, 30 และ 90 วันกำหนดช่วงแกนเวลา ไม่ได้ยืนยันว่ามีข้อมูลต่อเนื่องครบทุกวัน เส้นไม่มีการลากต่อไปยังเวลาปัจจุบันเมื่อไม่มีจุดข้อมูล

## ความครอบคลุมและหลักฐาน

แสดงจำนวนช่วงชั่วโมงที่มีข้อมูล / ช่วงชั่วโมงที่คร่อมเวลาที่เลือก พร้อมจำนวนครั้งที่เก็บล้มเหลวและช่วงชั่วโมงที่ไม่มีข้อมูล ช่วงแรก/สุดท้ายอาจไม่เต็มชั่วโมง ตัวเลขนี้จึงไม่ใช่เปอร์เซ็นต์ uptime ของระบบ

ปุ่มปฏิทินแสดงเวลาและสถานะแต่ละชั่วโมง แยกไม่มีข้อมูล, เก็บล้มเหลว, มีข้อมูลสำเร็จ และมีทั้งสำเร็จ/ล้มเหลวในชั่วโมงเดียวกัน

ปุ่มตารางแสดงอันดับ ยอดต้นช่วง ยอดปลายช่วง ยอดเพิ่ม อัตราต่อชั่วโมง เวลาที่เปรียบเทียบ ตัวนับหมวด/ทั้งหมด และรหัสรอบ/รายการต้นทาง แบ่งหน้าครั้งละ 10 แถว ไม่ต้องแสดงทุกแถวพร้อมกัน

ตารางแสดงระยะเวลาจริงเป็นวินาทีด้วย เพื่อคำนวณซ้ำได้แม้รอบเก็บข้อมูลไม่ตรงชั่วโมงพอดี เช่น 3,602.824108 วินาที ไม่ใช่ 3,600 วินาที อัตราที่แสดงปัดเป็นจำนวนเต็ม แต่ API เก็บผลคำนวณสองตำแหน่งทศนิยม

ตัวเลขจากกราฟคำนวณย้อนหลังได้แม้ลบ raw Snapshot ตาม retention แล้ว เพราะข้อมูลที่ใช้คำนวณและรหัสอ้างอิงถูกเก็บในประวัติรายชั่วโมง ไม่มีการเติมช่วงที่เครื่องปิดหรือ API ไม่ส่งข้อมูล

## ขอบเขตแพลตฟอร์ม

- YouTube อันดับรวม: มีกราฟอันดับ ยอดวิวเพิ่ม และสัดส่วนหมวด
- YouTube รายหมวด: มีกราฟอันดับและยอดวิวเพิ่มภายในหมวดนั้น ไม่แสดงสัดส่วนที่นับจากการขอข้อมูลหมวดละ 50
- Google: มีกราฟลำดับคำค้นตาม Google Trends เท่านั้น ไม่สร้างกราฟยอดวิวหรือสัดส่วนหมวดจากข้อมูลที่ไม่มี และไม่เอาปริมาณค้นหาโดยประมาณมาบวกรวมข้าม Snapshot

## การเก็บและ API

- `trend_snapshot_runs` / `trend_snapshot_items`: ข้อมูลต้นทางจริง
- `trend_history_buckets`: จุดแรกและสุดท้ายของแต่ละชั่วโมง พร้อมยอดวิวที่มีจริง, `view_metric_version`, `snapshot_item_id`
- `trend_history_attempts`: ผลสำเร็จ/ล้มเหลวรายขอบเขต ใช้แสดงช่องว่าง
- `GET /dashboard/public/history?platform=youtube&days=7&item_key=...`: รายละเอียดการเติบโตเฉพาะคลิปที่เลือก ชื่อและอันดับของรายการอื่นยังใช้เลือกคลิปได้
- เพิ่ม `video_category_id=20` เพื่อเลือกขอบเขตหมวดเกม ใช้ `platform=google` สำหรับคำค้น ไม่ผสมขอบเขต

การเติมข้อมูลเดิมทำเฉพาะ run เดียวกันที่ยังมี raw row: ไม่เอายอดปัจจุบันไปแทนยอดวันเก่า ไม่เปลี่ยนอันดับ เวลา หรือ Transcript และไม่ฝึกโมเดลใหม่

## ไฟล์ที่เกี่ยวข้อง

- `app/services/trend_history.py`: เก็บประวัติ เติม metadata เดิม ตรวจช่องว่าง คำนวณอันดับ/ยอดเพิ่ม/coverage
- `app/routes/dashboard.py`: API สาธารณะและตรวจ parameter
- `frontend_flutter/lib/models/trend_history.dart`: อ่านผลจาก Backend โดยรักษา null ให้แยกจาก 0
- `frontend_flutter/lib/widgets/trend_history_panel.dart`: ตัวเลือกคลิป/ช่วงเวลา กราฟ สถานะ ตารางหลักฐาน
- `tests/test_trend_history.py`: สูตร, ขอบเขต, missing data, negative counter, backfill และ retention
- `frontend_flutter/test/trend_history_test.dart`: การวาดเส้นขาด แท่งยอดเพิ่ม ตัวเลือกคลิป ตาราง และหน้าต่างเว็บขนาดเล็ก
- `scripts/browser/verify_dashboard_decisions.cjs`: ตรวจ API จริงและเว็บโดยไม่แก้ข้อมูล สร้างหลักฐานใน `artifacts/browser/dashboard-phase5/`

ข้อจำกัด: เก็บจุดต้น/ท้ายชั่วโมง จึงอาจไม่เห็นการขยับระหว่างสองจุด และการอยู่ในรายการที่ดึงมาเป็นเพียงหลักฐานจากรายการนั้น ไม่ใช่ตัวแทนผู้ชมทั้งหมดหรือหลักฐานว่าหัวข้อหนึ่งทำให้ยอดวิวเพิ่ม
