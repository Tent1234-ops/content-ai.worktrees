# Final Training and Presentation Handoff

อัปเดตภายหลังตามคำขอเจ้าของโครงการ: ยกเลิกเกณฑ์ 80% สำหรับการเปิดใช้โมเดลจำแนกหมวด เปิดรุ่น #58 แบบ Admin อนุมัติโดยไม่หมดอายุ และเอาแผนปรับคลิปออกจากหน้าผล ดู [Handoff ล่าสุด](classification-admin-approval-20261016-handoff.md) รายงานด้านล่างเป็นประวัติรอบก่อนหน้า ไม่ใช่สถานะ Active ปัจจุบัน

วันที่ตรวจรับ: 16 ตุลาคม 2026 (Asia/Bangkok)

## ขอบเขตและคำยืนยันของเจ้าของโครงการ

- ใช้ Dataset ชุดสุดท้าย ไม่ขอเก็บเพิ่มในรอบนี้ และไม่ย้าย Train/Validation/Test เดิม
- เจ้าของยืนยันว่าชุดล่าสุดเลือกตาม Prompt ของ Perplexity: คลิปปกติ ไม่ใช่ Shorts และไม่คัดตามยอดวิว/ไลก์ เป็น convenience sample ไม่ใช่ random sample
- เจ้าของยืนยันว่า **ยังไม่มีหลักฐานสิทธิ์ใช้ข้อมูลสำหรับ Outcome** จึงไม่เปลี่ยนสถานะสิทธิ์เป็นอนุมัติ ไม่ปลอม Probability และไม่เปิด Scenario ที่ยังไม่ผ่าน
- อนุญาตให้ใช้โมเดลจำแนกที่ดีที่สุดเพื่อพรีเซนต์ แม้ไม่ผ่านเกณฑ์ แต่ต้องติดป้าย `presentation_only` ไม่ใช่ `qualified`

## ข้อมูลที่ใช้จริง

- Dataset ทั้งหมด 663 แถว
- ผ่านสัญญาข้อมูลสำหรับงานจำแนก 433 คลิป: Phone 144, Camera 143, Laptop 146
- Train 311, Validation 49, Test เดิม 73; ช่อง Train/Validation/Test แยกกัน
- Unknown: Validation 10, Test 30, สำรอง 2 ไม่เอาข้อมูล Unknown Test กลับไปฝึก
- บันทึก provenance เฉพาะชุดใหม่ที่จับคู่กับ manifest ได้ 127 คลิป: Phone 43, Camera 45, Laptop 39
- การตรวจภาษาและข้อความแจ้งไม่มีคำบรรยายไม่พบปัญหาใน 433 คลิป แต่ **ไม่ใช่การรับรองว่าคำบรรยายครบและตรงเสียงทุกคำ**

## งานแก้ไข

1. ทางเทรนจากหน้า Admin ใช้ตัวเตรียมภาษาไทย `thai-transcript-v1` จริงแล้ว ไม่แบ่งคำตามช่องว่างอย่างเดียว และไม่ลบวรรณยุกต์ไทย
2. เกณฑ์ตรวจรับใช้ `validation-scope-thai-contrast-v2` ซึ่งปรับช่องว่างระหว่างข้อมูลฝึกและข้อความถอดเสียงด้วยวิธีเดียวกัน เลือกเกณฑ์จาก Validation ไม่ใช่คลิปเดโม
3. เก็บ feature version ใน artifact และรายงานเทรน โมเดลเก่าไม่ถูกเขียนทับ
4. เพิ่มการเปิดโมเดลชั่วคราวจาก run ที่ถูกล็อก พร้อมตรวจ hash, fingerprint, สิทธิ์ Admin, active model เดิม และวันหมดอายุ ไม่แก้ผลตรวจรับเป็นผ่าน
5. เปลี่ยน Whisper เป็น `medium` จากรุ่นที่ติดตั้งพร้อมใช้จริง บันทึกค่าก่อน/หลังไว้แล้ว ผลเก่าไม่เปลี่ยนย้อนหลัง
6. Health check ไม่นับ TikTok ที่ปิดใช้งานเป็นสาเหตุให้ระบบเสื่อมสภาพ แต่ยังรายงานความผิดพลาดจริงของ YouTube/Google
7. เพิ่มเครื่องมือตรวจผล ASR เดิมแบบ read-only และตรวจว่า Transcript/หมวด/ชุดข้อมูล/ผลวิเคราะห์เก่าไม่เปลี่ยน ยอดสถิติที่อัปเดตได้ต้องตรงกับ Observation จริง

## Outcome Predict: งานที่ยังไม่ผ่าน

การติดตั้งโค้ด UI/API/registry ไม่เท่ากับมีโมเดลผลตอบรับที่ผ่านการประเมิน

- Audit ก่อนดึงสถิติรอบล่าสุดมี source records 499 และผ่านโครงสร้าง 0 รายการ; หลังอัปเดตสถิติจริงในวันที่ 16 ตุลาคม ผ่านโครงสร้าง **96 คลิป**: Phone 34, Camera 35, Laptop 27 (`artifacts/final-presentation/20261016-final-state/outcome-source-audit.json`)
- 96 คลิปนี้เป็น Fit 72 และ Tuning 24 เท่านั้น ยังไม่มี Calibration/Independent Test ที่ผ่านครบเงื่อนไข ไม่ได้ย้ายชุด Test ของงานจำแนกมา Train
- จำนวนผ่านโครงสร้าง **ไม่เท่ากับอนุญาตให้ฝึกหรือเปิด Probability**: สิทธิ์ข้อมูลยัง unverified, training allowed 0, ไม่มี Frozen manifest/Outcome artifact
- ปัญหาที่พบมีทั้งรูปแบบ/กรอบการเก็บที่ยังไม่ยืนยัน, transcript ที่ไม่ใช่ทั้งคลิป, สถิติขาดหรือเก่า, ชุดทดสอบอิสระยังไม่รับรอง และหลักฐานสิทธิ์ยังไม่ยืนยัน
- จำนวนแต่ละเหตุผลทับซ้อนกัน ห้ามรวมเป็นจำนวนคลิปที่ต้องหาเพิ่ม
- Dataset builder และ training preflight รอบข้อมูลล่าสุดหยุดตามจริงเป็น `blocked_data_use` / `blocked` ไม่สร้าง artifact Outcome และไม่เปิด Independent Test หลักฐานอยู่ใน `20261016-final-state/outcome-preflight` และ `outcome-training`
- ค่าความมั่นใจของ Phone/Camera/Laptop **ไม่ใช่โอกาสที่ยอดวิวจะเพิ่ม**
- ยังรับรองไม่ได้ว่าเพิ่มอีกจำนวนตายตัวเท่าไรแล้วจะเปิด Predict ได้ เพราะยังต้องผ่านคุณภาพ ประชากรอ้างอิง การประเมิน และสิทธิ์ข้อมูล

สิ่งที่เสนอพรีเซนต์ได้คือการวิเคราะห์ข้อความและคำแนะนำพร้อมหลักฐานที่มีจริง โดยแยกสถานะส่วนประเมินผลตอบรับที่ยังไม่พร้อม ไม่อ้างว่าทำตามแล้ววิวเพิ่มแน่นอน

## ใช้พรีเซนต์อย่างไร

1. เปิด Dashboard ให้เห็น YouTube/Google จาก API จริงและเวลาที่เก็บ
2. เปิดไอเดียและประวัติ เลือกผล `review camera` **#40** เพื่อแสดงผลที่บันทึกแล้ว ไม่ต้องรอถอดเสียงในทุกครั้งที่สาธิต
3. อธิบายว่า Whisper ถอดเสียง, TF-IDF + SVM จำแนกหมวดและตรวจ Unknown, จากนั้นตรวจหัวข้อใน Transcript แล้วเทียบคลิปอ้างอิงเพื่อสร้างคำแนะนำภาษาไทย
4. เปิดข้อความต้นทางและหลักฐานของคำแนะนำ เลือกสิ่งที่จะนำไปปรับ และเปิดแผนฉบับที่บันทึกไว้ ชี้ว่าการเลือกยังไม่หมายถึงปรับคลิปเสร็จ
5. หน้า Admin แสดงรุ่น #57 และผลประเมินจริง พร้อมบอกว่าเป็นรุ่นสาธิตชั่วคราว ยังไม่ผ่านทุกเกณฑ์ ไม่ใช้คะแนน 97% ของคลิป Camera แทนคุณภาพคำแนะนำหรือโอกาสเพิ่มยอดวิว
6. ส่วน Outcome ให้แสดงสถานะยังประเมินไม่ได้ตามจริง ไม่บอกว่ามีโมเดลผลตอบรับที่เทรนเสร็จแล้ว

## ข้อจำกัดที่ยังเหลือ

- ส่วนวิเคราะห์/คำแนะนำและ workflow ที่ทดสอบพร้อมใช้สาธิต แต่ไม่รับรองว่าไม่มีข้อผิดพลาดกับทุกคลิป
- Phone Validation 77.78% และ Unknown Test เดิมยังหลุด 5/30 คลิป จึงคงป้าย presentation และวันหมดอายุไว้
- ASR ยังทำให้คำแนะนำซ้ำเนื้อหาที่พูดจริงได้ ต้องตรวจข้อความเทียบเสียง ไม่มีการแก้คำถอดเฉพาะคลิปเพื่อทำให้ผลดูดี
- **Outcome Predict แบบเปอร์เซ็นต์ยังไม่เสร็จตามเกณฑ์ใช้งานจริง**: ต้องเคลียร์หลักฐานสิทธิ์ จัดชุดประเมินที่เหมาะสม แล้วประเมินโมเดลจริง ไม่ข้าม gate และไม่อ้างว่าการเพิ่มหัวข้อทำให้วิวเพิ่มแน่นอน
