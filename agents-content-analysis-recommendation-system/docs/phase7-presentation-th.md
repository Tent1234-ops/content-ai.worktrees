# สรุป Phase 7 สำหรับพรีเซนต์

## สถานะที่ควรบอกอาจารย์

เตรียมเครื่องมือประเมินและเก็บผลจริงก่อน–หลังแล้ว แต่ **ยังไม่ผ่านการประเมินคลิปใหม่ครบสามหมวดและคลิปถ่ายเอง** เพราะยังไม่มีไฟล์พร้อมป้ายกำกับที่ยืนยันความเป็นชุดทดสอบอิสระ และยังไม่มีคะแนนคำแนะนำจากผู้ประเมินที่เป็นคน

ไม่ได้ฝึกโมเดลใหม่หรือเปลี่ยน Active Model ในรอบนี้ ใช้โมเดลหมายเลข 14 เดิม ใช้ Whisper small ถอดเสียงทั้งคลิป และดูช่วงเปิด 60 วินาที

## ผลที่มีจริง

| สิ่งที่ทดสอบ | ผล | ข้อจำกัด |
| --- | --- | --- |
| Transcript ชุด Test เดิม 17 รายการ | จำแนกถูก 17/17; Accuracy และ Macro F1 = 100% | เป็นชุดเดิมที่เคยประเมินแล้ว ไม่ใช่คลิปใหม่ และไม่ได้ทดสอบการถอดเสียง |
| คลิป Phone เดิม | ทาย Phone; confidence 98.16% | เป็นการตรวจซ้ำ ไม่ใช่หลักฐานความแม่นกับคลิปใหม่ |
| คลิปหูฟังเดิม | ทาย Phone; confidence 96.81% | เนื้อหาที่ถอดได้เป็นรีวิวหูฟัง แสดงปัญหาการรับคลิปนอกขอบเขต |
| คลิปคีย์บอร์ดเดิม | ทาย Phone; confidence 99.03% | ยังปฏิเสธคลิปอุปกรณ์เสริมไม่ได้อย่างน่าเชื่อถือ |
| คลิปเมาส์เดิม | ทาย Phone; confidence 96.86% | ปัญหาเดียวกัน และ Transcript มีคำถอดผิดหลายจุด |

ไฟล์วิดีโอ 11 ไฟล์ในโฟลเดอร์มีเนื้อหาไม่ซ้ำจริงเพียง 4 คลิป ตรวจจาก SHA-256 จึงไม่นับสำเนาการอัปโหลดเป็นตัวอย่างใหม่

Test 17 รายการมาจากไฟล์ที่เก็บไว้ตอนฝึกโมเดล: Phone 3, Camera 5, Laptop 9 ไม่มีตัวอย่าง Unknown ในชุดนี้ ตรวจแล้วไม่พบการซ้ำของ ID/ช่อง/ข้อความกับข้อมูลพัฒนาโมเดลและคลิปอ้างอิงตามเกณฑ์ตรวจของสคริปต์ แต่การตรวจอัตโนมัติไม่ได้รับประกันว่าข้อมูลทุกชิ้นเป็นอิสระอย่างสมบูรณ์

## แก้อะไรจากการทดสอบ

ก่อนแก้ คลิป Phone มีคำว่า `Dimensity` อยู่แล้ว แต่ระบบกลับเสนอคำนี้ในช่วงเปิดคลิป และไม่ได้แนบหลักฐานรายคำ

หลังแก้:

- ตรวจสิ่งที่พูดแล้วจาก Transcript เต็มและคำพ้อง ไม่ดูแค่คำที่แสดงได้สูงสุดบนหน้าจอ
- ไม่เอาคำที่ตรวจพบในช่วงเปิดกลับมาเป็นข้อเสนอแนะ
- เสนอหัวข้อที่ยังขาดและมีหลักฐาน พร้อม Dataset IDs ตัวอย่างต้นทางและเวลา
- ไม่อ้างว่าหัวข้อที่เสนอเคยเป็นประโยคเปิดคลิปที่ประสบความสำเร็จ เพราะ Transcript อ้างอิงบางรายการไม่มี Timestamp

สำหรับ Phone รอบนี้เสนอเรื่องการชาร์จ (พบใน 13/16 คลิปอ้างอิง), วัสดุและงานประกอบ (12/16) และการกันสั่น (9/16) จำนวนนี้เป็นหลักฐานว่าพบหัวข้อในคลิปอ้างอิง ไม่ใช่โอกาสที่ยอดวิวจะเพิ่ม

การเทียบก่อน–หลังใช้ข้อความถอดเสียง โมเดล การตั้งค่า และชุดอ้างอิงเดียวกัน จึงไม่ได้เอาผลต่างจากการถอดเสียงมานับเป็นผลของการแก้คำแนะนำ ส่วนไอเดียจากกระแสปัจจุบันไม่รวมในข้อสรุปก่อน–หลัง เพราะเวลาเก็บอาจต่างกัน

การตรวจโครงสร้างหลังแก้ไม่พบข้อผิดพลาดที่สคริปต์ตรวจได้ แต่ **ไม่ได้แปลว่าคำแนะนำถูกต้องทั้งหมด** ตัวอย่างคลิปหูฟังยังถูกจัดเป็น Phone จึงได้คำแนะนำผิดหมวดแม้ลิงก์อ้างอิงจะถูกต้อง

## อธิบายวิธีคิดให้เข้าใจง่าย

1. ถอดเสียงเพื่อให้ได้ข้อความและเวลา: ถ้าข้อความผิด ขั้นตอนหลังจากนี้อาจผิดตาม ต้องเปิดเสียงเทียบกับข้อความ
2. โมเดลจำแนกหมวดจากข้อความ: confidence คือความมั่นใจภายในโมเดล ไม่ใช่ผลตรวจว่าทายถูก เราเห็นแล้วว่าโมเดลมั่นใจ 99% แต่ทายอุปกรณ์เสริมเป็น Phone ได้
3. ดึงหัวข้อที่พบจริง และเลือกคลิปอ้างอิงหมวดเดียวกัน: ถ้าข้อ 2 ผิด ข้อมูลอ้างอิงก็ผิดกลุ่มตามไปด้วย
4. เสนอหัวข้อที่ยังไม่พบ พร้อมหลักฐาน: ตรวจจำนวนคลิป ความถี่ ที่มาและเวลาให้ย้อนกลับได้
5. ให้คนดูคลิปแล้วประเมิน: เกี่ยวข้องไหม, พูดไปแล้วหรือยัง, หลักฐานตรงไหม, เอาไปปรับคลิปได้จริงไหม
6. หากจะอ้างว่าเพิ่ม Engagement ต้องมีการทดลองผลลัพธ์อีกแบบหนึ่ง ผลจำแนกหมวดหรือจำนวนคลิปอ้างอิงอย่างเดียวพิสูจน์ไม่ได้

Accuracy คือสัดส่วนที่ทายหมวดถูกจากตัวอย่างที่มีคำตอบจริง ส่วน Recall รายหมวดคือคลิปหมวดนั้นทั้งหมดที่ระบบจับถูก และ Macro F1 คือค่าเฉลี่ย F1 ของแต่ละหมวดเพื่อไม่ให้หมวดที่มีตัวอย่างมากกลบหมวดอื่น รอบนี้รายงานเฉพาะหมวดที่มีตัวอย่างจริง และไม่เอา Unknown ที่ไม่มีตัวอย่างมาคิดเป็น 0 หรือ 100%

## สิ่งที่ต้องทำก่อนปิด Phase 7

- ส่งคลิปใหม่ Phone, Camera, Laptop ที่ไม่เคยใช้ปรับระบบ พร้อมคลิปถ่ายเองและคลิปนอกขอบเขต
- ระบุคำตอบจริงก่อนดูผลระบบ และยืนยันที่มา/ช่อง ไม่ตั้งหมวดจากชื่อไฟล์
- เก็บคลิปที่เพิ่งใช้แก้บั๊กไว้เป็นชุดตรวจซ้ำ หลังปรับระบบแล้วต้องมีชุดใหม่สำหรับประเมินสุดท้าย
- ตรวจข้อความถอดเสียงของคลิปที่ผิด เพื่อแยกว่าปัญหาเริ่มจาก ASR หรือจากโมเดล
- ให้คนกรอกแบบประเมินคำแนะนำ คะแนนที่ยังไม่มีคนกรอกต้องแสดงว่ายังไม่ได้ประเมิน
- พัฒนา Unknown ด้วยข้อมูลนอกขอบเขตที่หลากหลายและประเมินใหม่ ไม่ปรับ threshold ตามคลิปผิดเพียง 3 คลิปแล้วอ้างว่าจบ
