# 1. Dashboard และการเข้าถึงระบบ

[กลับสารบัญ](README.md)

## หน้าแรก / Dashboard

**ผู้ใช้ทำอะไรได้:** เปิดเว็บโดยยังไม่ Login ดูเทรนด์ YouTube หรือ Google เลือกหมวด YouTube เปิดรายละเอียด เปิดคลิปต้นทาง และดูประวัติ 7 วัน ส่วนการวิเคราะห์คลิปและข้อมูลส่วนตัวต้อง Login

**ประโยชน์:** ไม่ได้มีแค่รายชื่อคลิปดัง แต่ช่วยดูว่ารายการที่สนใจเคยอยู่ตรงไหน อันดับขยับหรือยอดวิวเพิ่มหรือไม่ และช่วงข้อมูลนั้นน่าเชื่อถือแค่ไหน

### ข้อมูลมาจากไหน

**YouTube:** `app/services/trends.py::_live_youtube_trending()` ส่งคำขอ:

```text
GET https://www.googleapis.com/youtube/v3/videos
part=snippet,statistics,contentDetails
chart=mostPopular
regionCode=TH
maxResults=50
videoCategoryId=24     เฉพาะเมื่อขอหมวดบันเทิง
```

`snippet` ให้ชื่อ ช่อง คำอธิบาย ภาพปก หมวด วันที่เผยแพร่; `statistics` ให้ยอดวิว ไลก์ ความคิดเห็น; `contentDetails` ให้ความยาว ในโค้ดจะแปลงความยาวอย่าง `PT3M20S` เป็น 200 วินาที

`50` เป็น **เพดานรายการต่อคำขอและงบข้อมูลของ Dashboard รุ่นนี้** ไม่ใช่จำนวนตัวอย่างที่พิสูจน์ทางสถิติว่าครอบคลุมประเทศไทย เอกสาร API อนุญาต `maxResults` สูงสุด 50 และมี `pageToken` สำหรับหน้าถัดไป แต่โปรเจคนี้ไม่ได้ไล่ทุกหน้า แหล่งข้อมูลอาจคืนไม่ครบ 50 และบางหมวดอาจไม่มี chart. [เอกสาร YouTube videos.list](https://developers.google.com/youtube/v3/docs/videos/list)

ขออันดับรวมหนึ่งชุด และขอ 12 หมวดแยกกัน; ชื่อ Category มี cache ไม่เรียก `videoCategories.list` ใหม่ทุกหมวด การเลือก “ทั้งหมด” คืออันดับรวม ไม่ใช่เอา 12 x 50 มาต่อแล้วจัดอันดับใหม่

เส้นทางอันดับรวมมี web fallback ถ้า YouTube API ใช้ไม่ได้ จึงต้องตรวจสถานะแหล่งข้อมูล/Log ไม่ควรพูดว่าทุกรอบมาจาก API สำเร็จเสมอ อันดับรายหมวดต้องใช้แหล่งข้อมูลตามขอบเขตหมวดนั้น

**Google:** โค้ดปัจจุบัน `_live_google_trending()` อ่านหน้า `trends.google.com/trends/trendingsearches/daily?geo=TH` ผ่าน HTTP แล้วใช้ `json5` แปลข้อมูลที่ฝังอยู่ใน `AF_initDataCallback` ไม่ใช่ RSS ในรุ่นนี้ และไม่ใช่ API ทางการแบบเดียวกับ YouTube

HTTP คือวิธีขอข้อมูลผ่านเว็บ ซึ่ง API ก็ใช้ HTTP ได้ แต่การอ่านโครงสร้างภายในหน้าเว็บไม่มีสัญญาว่ารูปแบบจะคงที่ Google เปลี่ยนหน้าได้ จึงต้องมีสถานะล้มเหลว/ข้อมูลเก่า และไม่อ้างความหมายของ field ที่ไม่ยืนยัน

### คำว่า Normalize ไม่ได้หมายถึงค่าทุกอย่างเท่ากัน

`normalize_live_item()` ใน `app/services/live_trend_snapshots.py` แปลงเป็นโครงสร้างกลางเพื่อเก็บและแสดงผล เช่น:

| ข้อมูลต้นทาง | ข้อมูลในระบบ | ความหมาย |
|---|---|---|
| YouTube `snippet.title` / Google query | `title` | ข้อความหัวเรื่อง ไม่ได้รวมว่าเป็นเหตุการณ์เดียวกันอัตโนมัติ |
| ตำแหน่งในรายการต้นทาง | `provider_rank` | ลำดับภายในแหล่งและขอบเขตที่ขอ |
| YouTube `viewCount` | `views` + `views_available` | ยอดดู ไม่ใช่จำนวนคนค้นหา |
| Google traffic ที่อ่านได้ | `search_volume` | ค่าปริมาณค้นหาจากต้นทาง ถ้าไม่ทราบเป็น `null` |
| เวลาที่คำขอสำเร็จ | เวลาใน Snapshot run | เวลาที่เราเห็นข้อมูล ไม่ใช่เวลาเริ่มเป็นกระแส |

บาง column ทางเทคนิคอาจมีค่าเริ่มต้น 0 แต่ต้องดู availability/source ประกอบ ไม่ถือว่า Google มียอดวิว YouTube เป็นศูนย์ และไม่เอาสองแพลตฟอร์มมารวมคะแนนจัดอันดับ

### รายละเอียดแต่ละรายการ

YouTube แสดงชื่อ/ช่อง อันดับปัจจุบัน การเปลี่ยนจากรอบก่อน หมวด วันที่เผยแพร่ ความยาว และยอดวิว/ไลก์/ความคิดเห็นเฉพาะที่ต้นทางมี ค่า “คำอธิบายจากช่อง” คือ description ที่เจ้าของคลิปเขียน **ไม่ใช่บทสรุปที่ AI ดูคลิปแล้วสร้าง** และไม่ได้มี Transcript ของทุกคลิป Top 50

Google แสดงคำค้น ปริมาณค้นหาประมาณเมื่ออ่านได้ แหล่งที่มาและเวลาที่เก็บ ต้องอธิบายว่าเป็นจำนวนการค้นหา/ค่าประมาณ ไม่ใช่จำนวนคนไม่ซ้ำ และเลขลำดับตาม feed ไม่ใช่หลักฐานว่าเป็นคำที่มีปริมาณค้นหามากที่สุดตลอดทุกช่วงเวลา

**ข้อจำกัด Google ที่ต้องพูดตรง ๆ:** ตัวเก็บรุ่นนี้ไม่ได้บันทึกช่วงเริ่ม/จบที่ Google ใช้รวมยอดค้นหาอย่างยืนยันได้ และใช้เวลาเก็บใส่ใน `published_at` ด้วย จึงห้ามนำ field นี้ไปอ้างว่าเป็นเวลาเริ่มเป็นเทรนด์จริง ข้อมูลจากหน้า Google Trends อย่างเป็นทางการอธิบายว่าเป็นกระแสการค้นหาที่เพิ่มขึ้นในช่วงล่าสุด แต่ไม่ทำให้ parser ภายในของเรารู้ช่วงเวลานับแน่นอนโดยอัตโนมัติ. [Google Trends Trending now](https://support.google.com/trends/answer/3076011?hl=en)

### รู้ได้อย่างไรว่าอันดับขึ้น

```text
อันดับขยับ = อันดับรอบก่อน - อันดับรอบใหม่
ตัวอย่าง #12 -> #5 = 12 - 5 = ขึ้น 7 อันดับ
ตัวอย่าง #5 -> #8 = 5 - 8 = ลง 3 อันดับ
```

ต้องเทียบ platform เดียวกัน, region เดียวกัน และ ranking_scope เดียวกัน เช่น `global` กับ `global` หรือ `category:24` กับ `category:24` เท่านั้น เพิ่งเข้าอันดับหมายถึง “ไม่พบในชุดก่อนและพบในชุดใหม่” ไม่ใช่ยืนยันว่าเพิ่งอัปโหลดหรือเพิ่งได้รับความนิยมครั้งแรก

### กราฟย้อนหลัง 7 วัน

| กราฟ | แกน X | แกน Y | ตอบคำถามอะไร |
|---|---|---|---|
| อันดับย้อนหลัง | เวลาเก็บจริง | เลขอันดับของคลิป/คำค้นที่เลือก | เคยอยู่ลำดับใด กำลังขึ้นหรือลงในชุดอันดับนี้ |
| ยอดวิวกำลังเพิ่มเร็วแค่ไหน | ปลายช่วงเวลาที่เปรียบเทียบ | ยอดวิวเพิ่มเฉลี่ยต่อชั่วโมง | ดังสะสมอยู่แล้ว หรือช่วงนี้มีคนดูเพิ่ม |
| หมวดไหนติดอันดับรวมมากขึ้น | เวลาเก็บจริง | ร้อยละของรายการในอันดับรวม | หมวดใดปรากฏบ่อยขึ้นในชุดอันดับรวมที่เราเก็บ |

```text
ยอดวิวเพิ่ม = ยอดวิวปลายช่วง - ยอดวิวต้นช่วง
เฉลี่ยต่อชั่วโมง = ยอดวิวเพิ่ม / จำนวนชั่วโมงที่ผ่านจริง
ตัวอย่าง 10,000 -> 13,000 ใน 2 ชั่วโมง = 1,500 วิว/ชั่วโมง

สัดส่วนหมวด = จำนวนคลิปหมวดนั้นในอันดับรวม / จำนวนคลิปทั้งหมดในรอบนั้น x 100
ตัวอย่าง เกม 10 จาก 50 = 20% ของรายการ ไม่ใช่ 20% ของผู้ชม
```

กราฟใช้ข้อมูลต้น/ท้ายชั่วโมงที่เก็บจริง มีตารางกดตรวจเวลา รหัส run และรหัส item ได้ ไม่ใช้รายหมวดที่ตั้งใจขอเท่ากัน 50 คลิปมาสรุปความนิยม เพราะจะกลายเป็นสะท้อนวิธีเก็บของเราเอง

“7 วันล่าสุด” คือวันนี้และย้อนหลังอีก 6 วันตามเวลาไทย ไม่ใช่ต้องมีข้อมูลครบ 168 ชั่วโมง หากเครื่องปิดหรือดึงล้มเหลว ช่วงนั้นขาดจริง ไม่เติมเป็น 0 ไม่ต่อเส้นข้ามช่วงขาด และหากพบแค่จุดเดียวจะแสดงจุดพร้อมบอกว่ายังเปรียบเทียบไม่ได้ รายการหลุดจากชุดอันดับไม่ใช่ยอดดูเป็นศูนย์

### เวลาเก็บกับเวลาเปิดเว็บเป็นคนละเรื่อง

ปัจจุบันกำหนดเก็บ 10 รอบ/วัน เวลา **14:00-23:00 Asia/Bangkok** ส่วน Browser อ่าน Database ผ่าน Backend ทุก **60 วินาที** การอ่าน DB ไม่กิน YouTube quota ซ้ำ ตัวเก็บทำงานผ่าน Backend หรือ Task Scheduler และใช้ `trend_collection_slots` ป้องกันทำรอบเดียวซ้ำ

ถ้าคอมพิวเตอร์/DB/อินเทอร์เน็ตไม่พร้อมก็ไม่มี observation จริง การเปิดคอมทีหลังไม่สามารถกู้ตัวเลขชั่วโมงที่ไม่เคยเก็บได้ ส่วน Windows launcher ใช้แบบไม่เปิด console เพื่อไม่รบกวน fullscreen

### ติดตามและแจ้งเตือน

Login สร้าง watch session และเก็บ baseline ของรอบข้อมูล จากนั้นเมื่อหน้าเว็บตรวจพบ Snapshot ใหม่ Backend เทียบรายการใหม่กับรอบก่อน พร้อมเงื่อนไขความสนใจและโหมดแจ้งเตือน: ทั้งหมด / เฉพาะที่ติดตาม / ปิด มีตัวเทียบหมวด YouTube แยกด้วย

การติดตามคำค้นในรุ่นนี้เทียบกับ **ชื่อเรื่องและ metadata** ไม่ได้แอบถอดเสียงทุกคลิป เทรนด์ใหม่คือรายการเข้าในชุดที่ตรวจ ไม่ใช่ push notification จาก YouTube โดยตรง การกดอ่านแล้วเปลี่ยนสถานะใน DB เฉพาะผู้ใช้คนนั้น

### หน้า Login / Register

Register รับชื่อ อีเมล รหัสผ่าน ตรวจซ้ำ แล้วเก็บ `users` รหัสผ่านเป็น hash ไม่เก็บ plaintext; Login ตรวจรหัสและสถานะบัญชี สร้าง access token + watch session; Logout ยุติ session หน้าเว็บและ Backend ต่างตรวจสิทธิ์ การซ่อนเมนู Admin อย่างเดียวไม่พอ

การเปิดหน้า Analyze/History โดยเป็นแขกจะเข้า Login; ผู้ใช้ทั่วไปเรียก Admin API เองก็ถูกปฏิเสธ
