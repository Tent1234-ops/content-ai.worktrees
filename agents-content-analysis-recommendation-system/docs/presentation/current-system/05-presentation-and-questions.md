# 5. วิธีพรีเซนต์และตอบคำถาม

[กลับสารบัญ](README.md)

## บทนำประมาณหนึ่งนาที

> โปรเจค Content AI เป็นเว็บช่วยผู้สร้างคอนเทนต์สองด้าน ด้านแรกแสดงข้อมูลวิดีโอและคำค้นจากแต่ละแพลตฟอร์ม พร้อมเก็บประวัติเพื่อเห็นการเปลี่ยนแปลง ด้านที่สองวิเคราะห์ข้อความจากเสียงในคลิปผู้ใช้ จำแนกหมวด และเปรียบเทียบกับคลิปอ้างอิงที่ตรวจสอบแล้ว เพื่อเสนอประเด็นและวิธีปรับเนื้อหา พร้อมให้ย้อนดูว่าข้อเสนออ้างอิงจากอะไร ระบบไม่ได้รับประกันยอดวิว และหากหลักฐานไม่พอจะงดข้อสรุปครับ

## ลำดับสาธิตที่แนะนำ

1. เปิด Dashboard แบบยังไม่ Login: แสดง YouTube/Google แยกกัน การ์ด รายละเอียด และลิงก์ต้นทาง
2. เลือกหมวด YouTube: อธิบายว่า #1 ของหมวดไม่ใช่ #1 ของทั้งหมด และทำไมจำนวนคลิปอาจต่ำกว่า 50
3. เปิดกราฟ 7 วันและตารางหลักฐาน: ชี้แกน X/Y ตัวเลขต้น/ปลาย เวลา และช่วงขาดจริง
4. Login: เปิดบุ๊กมาร์ก/กระดิ่ง อธิบายการติดตาม metadata และ Snapshot ที่ต่างรอบ ไม่รอให้เกิดเทรนด์ใหม่เพื่อให้เดโมผ่าน
5. เปิด Analyze: แสดง 5 นาที/Whisper small/Hook 60 วินาที และอธิบายทางเดินข้อมูลก่อนเริ่ม
6. เปิดผล#23ชื่อ `presentation check 20261004 Review Phone` จากโมเดลสาธิต#43ในประวัติAdmin#2 โดยชี้คำเตือนว่ายังไม่ผ่านเกณฑ์ก่อนอธิบายคำแนะนำ มีคลิปอ้างอิง26รายการ ช่วงความยาว77-136วินาที ส่วนผลเก่า#20ยังเก็บพฤติกรรมของ#14ไว้ ไม่ได้คำนวณทับ
7. เปิดหน้า Dataset และ Review: ชี้ที่มา label split และสิทธิ์นำไปใช้ ไม่ต้องแก้/ลบข้อมูลจริงระหว่างเดโม
8. เปิด Training: แสดง245คลิป, Unknownแบ่งครบ10/30แล้ว, Active#43เป็นข้อยกเว้นชั่วคราวสำหรับสาธิต ไม่ใช่รุ่นผ่านเกณฑ์ ไม่กดTrainซ้ำเพียงเพื่อให้ปุ่มมีการเคลื่อนไหว
9. เปิด Settings/Logs: แยกการตั้ง Whisper จาก classifier และยกกรณีแก้เครือข่ายที่ตรวจได้จาก log
10. จบด้วยสิ่งที่ทำงานแล้ว สิ่งที่ยังขาด และแผนประเมินคุณภาพคำแนะนำกับคลิปใหม่

ใช้ผลจริงที่บันทึกพร้อมรุ่น/คำเตือน ไม่อ้างว่าโหมดสาธิตผ่านการรับรองแล้ว ดู[โหมดสาธิตและวันหมดอายุ](../../implementation/presentation-model-20261005-handoff.md)

ข้อควรชี้ให้เห็นในผล#23: Whisper smallยังถอดคำเทคนิคบางคำผิด การไม่ตรวจพบคำในTranscript
ไม่ยืนยันว่าผู้ใช้ไม่ได้พูดจริง จึงต้องตรวจข้อความ/คลิปก่อนนำคำแนะนำไปใช้

## คำถามที่มักถูกถาม

### ทำไมไม่เปิด YouTube ดูตรง ๆ

เราเพิ่มการเก็บประวัติหลายเวลา การแยก scope อันดับ การดูช่วงข้อมูลขาด และเชื่อมการตรวจเนื้อหาผู้ใช้กับหลักฐานต้นแบบ แต่ไม่ได้อ้างว่าจัดอันดับดีกว่า YouTube หรือรู้ข้อมูลผู้ชมลับของแพลตฟอร์ม

### ทำไมเลือก 50 รายการ

เป็นเพดานต่อคำขอที่ API รองรับและขอบเขตการเก็บของรุ่นนี้ ช่วยจำกัดคำขอ/ขนาดข้อมูลและให้เลือกดูได้มากกว่าไม่กี่รายการ หน้าเว็บแสดงเพิ่มทีละ 12 ไม่ใช่เหตุผลว่า 50 เป็นตัวแทนทางสถิติของวิดีโอทั้งหมด จำนวนคืนจริงอาจน้อยกว่า

### ระบบรู้ว่าเทรนด์กำลังขึ้นได้อย่างไร

ใช้สอง Snapshot ในแพลตฟอร์ม ภูมิภาค และขอบเขตเดียวกัน อันดับเก่าลบอันดับใหม่ เลขอันดับน้อยกว่าคือดีขึ้น ถ้าจะดูยอดวิวโตต้องใช้ยอดวิวสองเวลา ไม่ใช้ยอดสะสมแทนความเร็ว

### “รีเฟรชทุก 60 วินาที” แปลว่า realtime ไหม

ไม่ใช่ หน้าเว็บตรวจ Database ทุก 60 วินาที ส่วนเก็บต้นทางปัจจุบันชั่วโมงละรอบในเวลาที่กำหนด ต้นทางก็มีจังหวะอัปเดตของตนเอง ข้อมูลที่เห็นคือสิ่งที่เราเก็บได้ ณ เวลาระบุ

### Google กับ YouTube เปรียบเทียบกันได้อย่างไร

ไม่ได้รวมอันดับกัน การมี field กลางช่วยจัดเก็บ/แสดง แต่ยอดค้นหาไม่ใช่ยอดดู เลือกดูคนละ tab ส่วน Google ยังมีข้อจำกัด parser และช่วงเวลายอดค้นหา ต้องไม่อ้างว่าเป็นคนไม่ซ้ำหรือจำนวนค้นหาทั้งประเทศที่ตรวจนับเอง

### Train AI อะไรเองบ้าง

ฝึกตัวจำแนก Phone/Camera/Laptop จาก Transcript ที่มนุษย์ตรวจ ส่วน Whisper เป็นโมเดลสำเร็จรูปที่ติดตั้งเพื่อถอดเสียง และ embedding เป็นตัวแทนข้อความที่ฝึกมาล่วงหน้า ไม่ได้ฝึก Whisper หรือ Transformer ใหญ่จากคลิป 245 รายการ

### Feature อยู่ตรงไหน

ตัวจำแนกมี TF-IDF ของคำ/กลุ่มตัวอักษร หรือ embedding ซึ่งเป็นเวกเตอร์ตัวเลข ส่วน Keyword ที่แสดงให้ผู้ใช้เป็นการสรุปสิ่งที่ตรวจพบ ไม่ใช่ feature ทั้งหมดของโมเดล และ metadata ใช้ด้านคัดข้อมูล/ควบคุมการเทียบ/สร้างหลักฐาน ไม่จำเป็นต้องใส่ทุก column เป็น input classifier

### ทำไมข้อมูลมาจาก YouTube ทั้งหมด แล้วเอาคลิป YouTube มาทดสอบอีก

มาจากแพลตฟอร์มเดียวกันไม่ใช่การรั่วโดยตัวมันเอง ปัญหาคือใช้วิดีโอ/ช่อง/ข้อความซ้ำหรือดู Test เพื่อปรับระบบซ้ำ เราจึงแบ่งตามช่องและตรวจซ้ำหลายรหัส แต่ยังต้องใช้คลิปถ่ายเองและกรณีใหม่เพื่อดูว่าระบบรับความต่างของโลกจริงได้หรือไม่ การตรวจ `Review_Phone.mp4` รอบนี้เป็น regression ไม่ใช่ข้อสอบใหม่

### Unknown 42 คลิปแบ่งครบแล้วหรือยัง

ครบแล้ววันที่4ต.ค.: Validation10, Test30, สำรอง2 จากแผนแบ่งใหม่ตามช่องที่ล็อกก่อนฝึก ไม่ใช่ขาดไฟล์หรือผู้ใช้ยังไม่ได้เก็บ โมเดลไม่ได้ฝึกUnknownเป็นหมวดที่สี่ และผลชุดจัดแบ่งใหม่นี้ไม่อ้างว่าเป็นfresh external test เพราะข้อมูลknownบางรายการเคยอยู่ในTrainของรุ่นก่อน

### ทำไมเปิดโมเดลทั้งที่ยังไม่ผ่านเกณฑ์

เปิด#43ชั่วคราวตามคำขอเพื่อสาธิตกระบวนการ ไม่ได้อ้างว่าผ่านเกณฑ์ รุ่นนี้ValidationรับLaptopได้3/5และปฏิเสธUnknown8/10 แต่ยังไม่ผ่านรายหมวด80%ทั้งหมด จึงมีคำเตือน วันหมดอายุ และยังตรวจรับแต่ละคลิป ไม่ใช่การลดเกณฑ์หรือทำให้คะแนนผ่าน ส่วนTestรอบใหม่ยังไม่ได้ทำ

### คำแนะนำจะทำให้ยอดวิวเพิ่มจริงไหม

ยังรับรองไม่ได้ เราตรวจว่าประเด็นพบในคลิปอ้างอิงและเกี่ยวข้องกับคลิปผู้ใช้ได้ แต่ความดังมีปัจจัยอื่น เช่น ขนาดช่อง หัวข้อ ภาพปก เวลาโพสต์ การเปรียบเทียบควบคุมช่อง/อายุ/รูปแบบช่วยลดความต่างบางส่วน ไม่เปลี่ยนความสัมพันธ์ให้เป็นเหตุและผล

### เพิ่ม Dataset แล้วต้องเทรนทุกครั้งไหม

ถ้าต้องการให้ classifier เรียนรู้ข้อมูลใหม่นั้น ต้องฝึกและเปิดรุ่นใหม่หลังผ่านเกณฑ์ แต่การคัดคลิปอ้างอิง/อัปเดตสถิติ/ไอเดียเทรนด์ทำงานใหม่ได้โดยไม่ฝึก classifier ทุกครั้ง ผลที่บันทึกไปแล้วใช้หลักฐานเดิม ไม่เปลี่ยนย้อนหลังเอง

### Median กับ Accuracy ต่างกันอย่างไร

Median เป็นค่ากลางของความยาวคลิปอ้างอิง ส่วน Accuracy เป็นสัดส่วนการทายหมวดถูก ทั้งสองไม่ใช่คะแนนเดียวกัน และช่วง P25-P75 ไม่ใช่ช่วงความมั่นใจว่าจะได้ engagement เท่าไร

### Log มีประโยชน์อย่างไร

บอกว่าใครทำอะไร เวลาใด สำเร็จหรือไม่ เช่น แก้ Transcript, ฝึกโมเดล, เก็บเทรนด์ล้มเหลว วันที่ตรวจเราพบปัญหาเชื่อมต่อจาก Log และแก้สภาพแวดล้อมเซิร์ฟเวอร์ได้ ไม่ต้องเดาว่าเกิดจาก API quota หรือสูตรกราฟ

### ตอนนี้จบโปรเจคแล้วหรือยัง

ควรตอบว่า “workflowเว็บไซต์หลักและการบันทึกทดสอบแล้ว ข้อมูลUnknownแบ่งครบและฝึกใหม่แล้ว แต่โมเดลยังไม่ผ่านValidationด้านการรับLaptopและปฏิเสธUnknown และการทดสอบประโยชน์คำแนะนำกับคลิป/ผู้ประเมินใหม่ยังไม่ครบ” ไม่ตอบว่าพร้อมทุกส่วนเพียงเพราะunit testsผ่าน

## คำที่ควรหลีกเลี่ยง

- “เพิ่มคำนี้แล้ววิวเพิ่มแน่นอน” ให้ใช้ “พบหัวข้อนี้ในคลิปอ้างอิงที่ผ่านเกณฑ์”
- “Confidence 98% จึงแนะนำถูก 98%” ให้แยกคะแนนทายหมวดออกจากคุณภาพคำแนะนำ
- “Google อันดับหนึ่งคือคนค้นหามากที่สุดแน่นอน” ให้ระบุว่าเป็นลำดับในข้อมูลต้นทางที่เก็บได้
- “ช่วงกราฟที่หายคือไม่มีคนสนใจ” ให้ใช้ “ช่วงนั้นไม่มีข้อมูลสังเกตที่เทียบได้”
- “มี245คลิปจึงฝึกด้วย245” ให้บอกว่ารอบ4ต.ค.ใช้178 fit, 30 validation, 37 test
- “ผล Test ใหม่” สำหรับคลิปที่เคยใช้แก้ bug ให้เรียก regression หรือผลทดสอบเดิม
- “จัดกลุ่ม” แทน “จำแนกหมวด” โดยไม่แยกว่าเป็นคนละวิธี

## ก่อนเข้าห้องพรีเซนต์

เปิด MySQL และใช้ `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start_demo.ps1` จากโฟลเดอร์โปรเจค เปิด `http://127.0.0.1:8080/#/dashboard` ดูเวลาเก็บข้อมูลและสถานะแหล่ง อย่าปิด Backend ระหว่าง ASR อย่าเปิดเผย API key/รหัสผ่านในสไลด์ และเตรียมภาพหลักฐานไว้สำหรับกรณีอินเทอร์เน็ตสถานที่จริงมีปัญหา
