# อ่านหน้าเทรนและนำเข้า Dataset ให้อธิบายต่อได้

ตรวจตามโค้ดวันที่ 7 ตุลาคม 2026 คู่มือนี้อธิบายระบบที่มีอยู่ ไม่ได้สั่งเทรนหรือเปิดโมเดลใหม่

## 1. ต้องแยกสามงานนี้ออกจากกันก่อน

| งาน | รับอะไร | ได้อะไร | ฝึกจากปุ่มหน้า Admin หรือไม่ |
|---|---|---|---|
| Whisper ถอดเสียง | เสียงจากวิดีโอ | Transcript และเวลาที่ตรวจพบคำพูด | ไม่ใช่ หน้านี้ไม่ได้ฝึก Whisper |
| โมเดลจำแนกหมวด | Transcript | Phone / Camera / Laptop หรือไม่รับผลเป็น Unknown | ใช่ ปุ่มเทรนใช้กับส่วนนี้ |
| ระบบแนะนำ | หมวดที่รับได้ + เนื้อหาผู้ใช้ + คลิปอ้างอิง | ประเด็นที่ควรเพิ่ม วิธีทำ ตัวอย่างประโยคและหลักฐาน | ไม่ใช่โมเดลเดียวกัน ใช้การเปรียบเทียบหลักฐานและแม่แบบ |

ตัวอย่าง: เสียงว่า “กล้องตัวนี้โฟกัสเร็ว” ถูกถอดเป็นข้อความ จากนั้นตัวจำแนกบอกว่าเป็น Camera ระบบแนะนำจึงค้นหลักฐานกลุ่ม Camera มาดูว่ามีประเด็นที่ยังไม่ตรวจพบและเกี่ยวข้องหรือไม่ ไม่ใช่เพิ่มคำแล้วรับประกันยอดวิว

## 2. หน้าเทรนโมเดล AI ใช้อย่างไร

เส้นทาง: `/admin-training`

### ขั้นที่ 1 ดูตาราง “ข้อมูลสำหรับเทรน”

- **หมวด**: Label ที่ต้องการให้โมเดลแยก ปัจจุบันคือ Phone, Camera, Laptop
- **ฝึก (Train)**: ข้อความและคำตอบที่ให้โมเดลเรียนรู้
- **ตรวจสอบ (Validation)**: ข้อมูลที่แยกไว้ตรวจการเลือกวิธี/นโยบายรับผล โดยเฉพาะการปฏิเสธ Unknown ไม่ใช้เป็นชุดสอบสุดท้าย
- **ทดสอบ (Test)**: ชุดตรวจผลหลังออกแบบแล้ว ไม่ควรนำผลรายคลิปกลับไปปรับแล้วอ้างว่าเป็น Test ใหม่
- **ช่อง**: จำนวนช่อง YouTube ที่เป็นเจ้าของคลิป ไม่ใช่จำนวนหมวด การมีคลิปจากหลายช่องช่วยลดการจดจำสไตล์ช่องเดียว
- **พร้อมเทรน**: จำนวนและการแบ่งข้อมูลผ่านขั้นต่ำ ไม่ได้แปลว่าโมเดลที่จะได้แม่นหรือผ่านเกณฑ์เปิดใช้

“แบ่งตามช่อง” คือให้คลิปจากช่องเดียวกันอยู่ชุดเดียว เช่น ช่อง A ทั้งหมดอยู่ Train ช่อง B อยู่ Validation ช่อง C อยู่ Test ไม่ใช่นำคลิปช่อง A ไปกระจายสามชุด เพราะอาจจำสำนวนและผู้พูดเดิมจนคะแนนดูดีเกินการใช้งานกับคนใหม่

Unknown เป็นตัวอย่างนอกขอบเขตสำหรับตรวจการปฏิเสธ เช่น หูฟัง/คีย์บอร์ด ไม่ใช่การเพิ่มหมวดที่สี่ให้ระบบสร้างคำแนะนำเฉพาะหูฟัง

### ขั้นที่ 2 กด “เริ่มเทรนและเปรียบเทียบ”

1. Backend ตรวจสิทธิ์ Admin ตรวจว่าไม่มีงานเทรนซ้อน และ fingerprint ของ Dataset ยังตรงกับตอนเปิดหน้า
2. สร้างแถวงานใน `model_training_runs` แล้วให้ worker ทำงานเบื้องหลัง ไม่ปล่อย HTTP request รอจนฝึกเสร็จ
3. อ่านเฉพาะข้อมูลที่ผ่านเงื่อนไข ไม่อ่านทุกแถวของ `dataset_contents` ไปฝึกรวมกัน
4. แปลงข้อความเป็นตัวเลข แล้วทดลองโมเดลตามรายการที่โค้ดกำหนด
5. ประเมินและบันทึกผล พร้อมไฟล์โมเดล ไม่ได้สลับ Active Model ให้อัตโนมัติ

รอบฝึกปกติมี Complement Naive Bayes, Logistic Regression, Linear SVM และ multilingual embeddings + Logistic Regression ถ้าเครื่องไม่มีไฟล์ embedding ที่จำเป็น รอบเว็บจะข้ามโมเดลนั้นพร้อมเหตุผล ไม่ดาวน์โหลดเงียบ ๆ

TF-IDF แปลงคำและกลุ่มตัวอักษรเป็นคุณลักษณะเชิงตัวเลขให้ตัวจำแนกเรียนรู้ ส่วน embedding แปลงข้อความเป็นเวกเตอร์ที่แทนเนื้อหา ดังนั้นโมเดลไม่ได้จำแค่ว่าคำไหนมีความถี่สูงสุด

### ขั้นที่ 3 อ่าน “รอบเทรนล่าสุด” และ “โมเดลที่บันทึกไว้”

| ข้อความ | อ่านอย่างไร |
|---|---|
| รหัสรอบ | หนึ่งคำสั่งฝึกเปรียบเทียบหลายโมเดล อาจมี Model ID หลายตัวจากรอบเดียว |
| โมเดล / รุ่น | วิธีจำแนกและรุ่นของไฟล์ ไม่ใช่จำนวนคลิป |
| ข้อมูลฝึก | จำนวนตัวอย่าง Train ที่โมเดลใช้ |
| CV ถูก / F1 | คะแนนจากแบ่งข้อมูลฝึกเป็นรอบ ๆ ตามช่อง ไม่ใช่คะแนนบน Test และไม่ใช่ Validation ทั้งชุด |
| Test ถูก / F1 | คะแนนบนชุดทดสอบที่แยกไว้ เครื่องหมายขีดหมายถึงไม่มีค่านั้น ไม่ใช่ศูนย์ |
| ดูผลประเมิน | เปิดคะแนนแยกหมวด ตัวอย่าง และตารางจริงเทียบกับที่ทาย |
| กำลังใช้งาน | เป็นรุ่นที่ถูกเลือกใน registry แต่ยังต้องอ่านสถานะความพร้อม/วันหมดอายุด้วย |
| เปิดใช้โมเดล | เลือกรุ่นสำหรับงานวิเคราะห์ใหม่ได้เมื่อ Backend ตรวจผ่าน ไม่ใช่เลือกเลขสูงที่สุดแล้วข้ามเงื่อนไข |

**Accuracy**: ทายหมวดถูกกี่ตัวจากทั้งหมด เช่น ถูก 24 จาก 30 คือ 80%

**Recall ของ Camera**: จากคลิปที่จริง ๆ เป็น Camera โมเดลรับเป็น Camera ได้กี่คลิป เช่น ถูก 8 จาก 10 คือ 80%

**Precision ของ Camera**: จากคลิปที่โมเดลบอกว่าเป็น Camera มี Camera จริงกี่คลิป

**F1 ของหมวดหนึ่ง**: รวม Precision และ Recall ด้วยสูตร `2 * Precision * Recall / (Precision + Recall)`; **Macro F1** คือเฉลี่ย F1 ของแต่ละหมวดอย่างเท่าเทียม จึงไม่จำเป็นต้องเท่ากับ Accuracy โดยเฉพาะเมื่อจำนวนคลิปแต่ละหมวดไม่เท่ากัน

**Unknown rejection**: คลิปนอกขอบเขตที่ระบบปฏิเสธได้ ควรอ่านคู่กับความถูกต้องของสามหมวด เพราะการปฏิเสธทุกคลิปไม่ใช่โมเดลที่ดี

**Confusion matrix**: ตารางแถวเป็นหมวดจริง คอลัมน์เป็นหมวดที่ทาย ช่องนอกแนวทแยงคือความสับสน เช่น Laptop ถูกทายเป็น Phone

เกณฑ์ 80% ในระบบเป็นนโยบายของโปรเจค ไม่ใช่ข้อรับรองสากล การเลือกอันดับโมเดลใช้สถานะนโยบายรับผลและ Grouped CV ก่อน ไม่ใช้ Test จัดอันดับ และการ Activate ยังตรวจผล Unknown, ไฟล์ที่ประเมิน, hash และเงื่อนไขอื่นอีก

### ขั้นที่ 4 หลังเทรนได้ไฟล์แล้วทำอะไร

```text
ข้อมูลตรวจแล้ว -> แบ่งชุด -> แปลงข้อความ -> ฝึก/ประเมิน
-> model.joblib + รายงานผล + manifest ของข้อมูล
-> Admin ตรวจผล -> เปิดใช้รุ่นที่ผ่าน
-> งานวิเคราะห์ใหม่โหลดตัวแปลงข้อความและตัวจำแนกจากไฟล์นี้
```

- `model.joblib` เก็บวัตถุที่เรียนรู้แล้ว รวมตัวแปลงข้อความ/ตัวจำแนกตามชนิดโมเดล ไม่ใช่โปรแกรม `.py` ใหม่ที่ต้องนำไปต่อหน้าเว็บเอง
- `classification_models` เก็บทะเบียนรุ่น ตำแหน่งไฟล์ สถานะและรุ่นที่ Active
- `model_evaluation_metrics` เก็บคะแนนว่าได้เท่าไร ใช้ชุดใด ประเมินตัวอย่างเท่าไร
- `model_training_runs` เก็บงานฝึก สถานะ ขั้นตอน เวลา และปัญหา
- ผลวิเคราะห์เก่ามีรุ่นและหลักฐานที่บันทึกไว้ ไม่เปลี่ยนตามโมเดลที่เปิดใหม่อย่างเงียบ ๆ

**สถานะที่ต้องระวัง ณ วันที่เขียน:** รุ่น #43 เป็น `presentation_only` ไม่ใช่รุ่นที่ผ่านเกณฑ์ปกติ สิทธิ์สาธิตเดิมหมดวันที่ 6 ต.ค. 2026 เวลา 23:42 น. งานปรับหน้าจอครั้งนี้ไม่ได้ต่ออายุหรือฝึกใหม่ ต้องอ่าน readiness ปัจจุบันจากหน้า Admin อย่าบอกอาจารย์ว่าผ่าน 80% แล้วเพียงเพราะมีเครื่องหมาย Active

## 3. สองตัวเลือกในหน้านำเข้า Transcript ต่างกันอย่างไร

| ตัวเลือก | ความหมาย | ตัวอย่างเหตุผลที่เลือก |
|---|---|---|
| ข้อมูลจำแนกหมวด | บันทึก `collection_strategy=classification_diverse` ต้องการตัวอย่างเนื้อหาหลากหลายเพื่อแยกหมวด | คลิปกล้องหลายยี่ห้อ หลายช่อง ทั้งคลิปดังและธรรมดา |
| คลิปผลตอบรับสูง | บันทึก `collection_strategy=recommendation_high_performance` ผู้เก็บคัดคลิปเพราะสนใจผลตอบรับ | คลิปรีวิวกล้องที่มีสถิติน่าสนใจ ต้องการใช้ศึกษาประเด็นที่กล่าวถึง |

**ทั้งสองแบบเข้า `dataset_contents` เดียวกันเมื่อ Review อนุมัติแล้ว** ก่อนอนุมัติ NotebookLM import สร้าง candidate ในไฟล์ของรอบนำเข้า และบันทึกรอบใน `dataset_collection_runs`; การตัดสินเก็บใน `dataset_review_events`

ตัวเลือกนี้เป็นประวัติว่า “เราเลือกเก็บมาทำไม” ไม่ใช่สวิตช์บังคับว่าข้อมูลใช้ได้ทางเดียว โค้ดอนุมัติยังดูหมวดและ split: หมวดในขอบเขตอาจใช้ฝึกได้ และแถว Train อาจมีสิทธิ์เป็นคลิปอ้างอิง แต่ Validation/Test และข้อมูลที่ชนกับช่อง/เนื้อหาของชุดประเมินต้องไม่เอามาสร้างคำแนะนำ

ระบบแนะนำยังคัดหมวดให้ตรง ตรวจคุณภาพข้อความ ที่มา วันที่และสถิติ แล้วคำนวณคัดกลุ่มผลตอบรับสูงจริง ไม่ได้เชื่อคำว่า “คลิปผลตอบรับสูง” ที่ผู้กรอกเลือกเพียงอย่างเดียว และไม่ถือว่ายอดสูงเกิดจากการพูดคำใดคำหนึ่งแน่นอน

**ผลต่อการทำงาน:** เพิ่มข้อมูลแล้วจะมีผลต่อชุดอ้างอิงของงานใหม่ได้เมื่อผ่านเงื่อนไข แต่ตัวจำแนกที่เป็นไฟล์โมเดลเดิมจะไม่เรียนรู้ข้อมูลเพิ่มเอง ต้องเทรนและเปิดใช้รุ่นใหม่

## 4. ทำไมยังเก็บเครื่องมือ Dataset สามอย่าง

ย้ายจากแท็บบนสุดไปเมนูจุดสามจุด “เครื่องมือ Dataset เพิ่มเติม” เพื่อให้หน้าแรกเหลือรายการและตัวกรองหมวด

- **คุณภาพและแผนเก็บข้อมูล**: ตอบว่า “ข้อมูลขาดอะไร ใช้ฝึก/อ้างอิงได้หรือยัง ต้องเก็บหมวดหรือช่องใดเพิ่ม” ไม่ใช่กราฟจัดอันดับคลิปดัง เช่นมี Transcript แต่ไม่มีวันที่เก็บสถิติ ก็ยังอ้างยอดล่าสุดไม่ได้
- **สถิติและการเติบโต**: ตอบว่า “ตัวเลขวิว/ไลก์เก็บเมื่อใด เพิ่มขึ้นจริงระหว่างเวลาไหน” จำเป็นเวลาตรวจคำแนะนำที่อ้างผลตอบรับ ไม่ต้องถอด Transcript ใหม่เพื่ออัปเดตตัวเลข และไม่ควรตีความยอดสะสมว่าเป็นความเร็วเติบโต
- **ถังขยะ**: ลบผิดแล้วกู้ได้ โดยรักษาหลักฐานของผลวิเคราะห์เก่า การลบไม่ทำให้โมเดลที่ฝึกแล้วลืมทันที ต้องฝึกใหม่ถ้าต้องการตัดข้อมูลออกจากสิ่งที่โมเดลเรียนรู้

ทั้งสามอย่างเป็นเครื่องมือดูแลระบบ ไม่จำเป็นต้องแสดงแก่ผู้ใช้ทั่วไป แต่การตัดทางกู้คืนและทางตรวจหลักฐานทิ้งจะทำให้ดูแลข้อมูลยากขึ้น

## 5. ตัวอย่างคำอธิบายสั้นสำหรับพรีเซนต์

> ระบบแยกการถอดเสียง การจำแนกหมวด และการแนะนำออกจากกันครับ หน้า Admin ใช้ตรวจข้อมูลแล้วสั่งฝึกตัวจำแนกหลายวิธีเทียบกัน เรากันข้อมูลตามช่องเพื่อไม่ให้จำสำนวนของช่องเดิมไปได้คะแนนสอบสูงเกินจริง เมื่อเทรนเสร็จจะได้ไฟล์โมเดลและคะแนนประเมิน แต่ต้องผ่านเกณฑ์ก่อนเลือกใช้กับงานใหม่ ส่วนคำแนะนำใช้คลิปอ้างอิงที่ตรวจที่มาได้ โดยไม่เอาคลิป Test กลับมาเป็นต้นแบบ และไม่อ้างว่าการเพิ่มหัวข้อจะทำให้ยอดวิวเพิ่มแน่นอน
