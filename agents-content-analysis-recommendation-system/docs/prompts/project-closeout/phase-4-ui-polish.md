# Closeout Phase 4: เก็บ UI ของรุ่นส่ง

อ่าน README และ scope/Handoff ล่าสุด งานนี้ตกแต่งและลดความสับสนของ flow ที่มีอยู่ ไม่เปลี่ยนโมเดล สูตร การจับคำ หรือ contract ข้อมูล และห้ามซ่อนข้อผิดพลาดเพื่อให้ภาพดูสมบูรณ์

## แนวทาง

1. อ่าน theme/components ปัจจุบันแล้วปรับร่วมกัน: typography ภาษาไทย, สี/contrast, spacing, borders, icon size, input/button/table states ไม่มีการเปลี่ยน framework หรือเริ่มดีไซน์ใหม่ที่ต้องรื้อ routes
2. ใช้ข้อความไทยสม่ำเสมอและกระชับ คงศัพท์เทคนิคเฉพาะส่วนรายละเอียดที่จำเป็น; แก้ช่องว่างใหญ่/ข้อความชื่อคลิปยาว ไม่ลดขนาดตัวอักษรจนอ่านไม่ได้
3. ใช้ icons จาก library เดิมพร้อม tooltip, tabs สำหรับมุมมอง, controls ที่ตรงชนิดข้อมูล ไม่ทำทุกอย่างเป็นปุ่มข้อความทรงกล่อง
4. Page section เป็น layout/band ไม่ซ้อน card ภายใน card; cards ใช้กับรายการคลิปและส่วนที่จำเป็นจริง ใช้ภาพปกคลิปจริง ไม่สร้างภาพสินค้า/กราฟปลอมเพื่อให้หน้าเต็ม
5. ไม่เพิ่มข้อความอธิบายสไตล์/วิธีใช้/ปุ่มลัดบนหน้าจอเพื่อเติมความโล่ง ใช้หัวข้อข้อมูลและ empty/error/status ที่จำเป็น

## หน้าเรียงตามความสำคัญ

### Dashboard สาธารณะ

- ผู้เข้าใหม่เห็น Content AI และคลิป/คำค้นจริงได้ในช่วงต้นหน้า ไม่ให้ filter/กราฟสูงจนกลบรายการทั้งหมด
- YouTube cards: ภาพปก ชื่อ ช่อง วิว ความยาว อันดับ พร้อมรายละเอียด/ต้นทาง/ดูเพิ่มเติมตาม flow เดิม
- Google ใช้รายการคำค้นและตัวเลข/เวลา/ข้อจำกัดที่มีจริง ไม่ยืม layout วิดีโอที่ไม่มีภาพหรือช่องมาใช้
- กราฟมีแกน หน่วย ช่วงเวลา source/scope/coverage ชัด คงช่องว่างข้อมูล ไม่เพิ่มกราฟวงกลมเพียงเพราะทำได้
- TikTok ที่ยังไม่มีข้อมูลให้จัดตาม scope ที่ยืนยันแล้ว หากยังอยู่ต้องเป็นสถานะไม่พร้อมที่ชัด ไม่ทำเหมือนโหลดล้มเหลวหรือมี trend จริง

### Upload / Result / History

- Upload เห็นข้อจำกัดจาก settings จริง เลือกไฟล์/ยกเลิก/กำลังถอดเสียง/สำเร็จ/ผิดพลาดชัด ไม่ใช้เปอร์เซ็นต์หลอกที่ค้างจนดูเหมือนเสร็จ
- Result เรียง “พบอะไร -> ควรเพิ่มอะไร -> เพราะอะไร”; แสดง 2-3 ข้อหลัก, Keyword ดิบและหลักฐานเปิดดูเพิ่ม; Unknown/หลักฐานไม่พอมีข้อความตรงสาเหตุ
- ผู้ใช้คัดลอกตัวอย่าง เลือกนำไปปรับ บันทึกแผน กลับ History และเปิดต่อได้ง่าย ไม่ตี checkbox ว่าปรับเสร็จแล้ว
- History ชื่อคลิปอ่านได้, วันที่และหมวดชัด, สถิติไม่กลบรายการทั้งหมด; ผลเก่าและรุ่นโมเดลเดิมไม่ถูกเปลี่ยนเพราะ UI ใหม่

### Login / Register / Admin

- Auth มี validation/loading/error และเส้นทางกลับ Dashboard ที่ทำงานจริง
- Admin ทั้ง 7 หน้าจัดวางตาราง/ฟอร์ม/ปุ่มหลักสม่ำเสมอ ไม่ซ่อน destructive actions ไว้ในปุ่มทั่วไป
- Training และ Settings แสดง readiness ของรุ่นที่ Active จริงตาม Phase 1 ไม่ให้คะแนนเก่าดูเหมือนรับประกันความพร้อม
- Dataset/Review/Trash, Users, Logs มี loading/empty/error และยืนยัน destructive actions ไม่ต้องสร้าง Admin Console รวมลิงก์ขึ้นมาอีก

## เกณฑ์ผ่าน

- Playwright หรือ browser จริงบน build ล่าสุด 1440x900 และ 1000x800 อย่างน้อย ตรวจ screenshot ของหน้าหลักและเปิดรายละเอียด/ฟอร์ม ไม่ใช่เช็กแต่ HTML
- ไม่มี text/controls overlap, horizontal overflow ที่ไม่ตั้งใจ, blank media หรือ clipping ของปุ่ม; ตารางกว้างมีพื้นที่เลื่อนที่ตั้งใจ ไม่ดันทั้งหน้า
- ตรวจ hover/focus/disabled/loading/error/empty เท่าที่เกี่ยวกับการแก้, คีย์บอร์ดใช้งานฟอร์มหลักได้
- ข้อมูลและ API requests ยังคงเดิมตาม contract; UI tests และ regression ที่เกี่ยวข้องผ่าน ไม่มีปุ่ม success ก่อน save จริง
- ไม่เพิ่ม Mobile app, UI framework ใหม่ หรือคำแนะนำ/ข้อมูลจำลองลงผลจริง
