# Prompt สำหรับพัฒนาคำแนะนำ Phase 5-7

เตรียมจากโค้ดที่ตรวจเมื่อ 29 กันยายน 2026 เป็นเอกสารมอบหมายงานเท่านั้น ยังไม่ได้พัฒนาฟีเจอร์ Phase 5-7 ตามเอกสารชุดนี้

หมายเลข Phase ในโครงการเคยใช้หลายรอบ ชุดนี้หมายถึง **คำแนะนำ -> แผนปรับคลิป -> เทียบฉบับแก้ไข -> ประเมินประโยชน์** ไม่ใช่ Phase 5 Dashboard หรือ Phase 6 UI ในเอกสารเก่า

## ใช้ทีละ Phase

1. ให้ผู้ทำงานอ่าน [Phase 5: เพิ่มน้ำหนักหลักฐาน](phase-5-evidence-comparison.md) แล้วทำเฉพาะ Phase นี้ให้จบ
2. ตรวจรายงานส่งต่อ โดยเฉพาะจำนวนข้อมูลจริงที่ใช้เปรียบเทียบได้ ก่อนเริ่ม [Phase 6: เทียบฉบับแก้ไข](phase-6-revision-comparison.md)
3. หลังฟีเจอร์นิ่ง ให้ล็อกเวอร์ชันและทำ [Phase 7: ประเมินประโยชน์](phase-7-utility-evaluation.md)

ข้อความสำหรับเริ่มงานแต่ละรอบ:

```text
อ่าน docs/prompts/recommendation-roadmap/phase-5-evidence-comparison.md
แล้วดำเนินงานตาม Prompt นั้นให้ครบ ทำเฉพาะ Phase 5
อ่านโค้ดจริงก่อนแก้ รักษางานที่ค้างอยู่ และอย่าประกาศว่าผ่านการประเมินจริงถ้ายังขาดข้อมูล
```

รอบถัดไปเปลี่ยนชื่อไฟล์และหมายเลข Phase เป็น 6 หรือ 7 ไม่จำเป็นต้องแนบประวัติสนทนาทั้งหมด
หากเปลี่ยน Session ให้แนบรายงานส่งต่อของ Phase ก่อนหน้าด้วย

## สิ่งที่จะได้

| Phase | ผู้ใช้ได้อะไร | ต้องมีข้อมูลอะไรเพิ่ม |
| --- | --- | --- |
| 5 | เปิดดูว่าคลิปที่กล่าวถึง/ยังไม่ตรวจพบหัวข้อมีผลตอบรับต่างกันอย่างไร พร้อมข้อจำกัด | คลิปทั่วไปและคลิปผลตอบรับสูงในกลุ่มใกล้เคียงกัน รวมคลิปจากช่องเดียวกันที่มี/ไม่มีหัวข้อนั้น |
| 6 | อัปโหลดฉบับแก้ไขแล้วเทียบกับแผนเดิม พร้อมข้อความที่ตรวจพบจริง | คลิปต้นฉบับ ฉบับแก้ไข และแผนที่บันทึกแล้ว |
| 7 | รายงานแยกความแม่นของหมวดกับความเข้าใจง่าย/ประโยชน์ของคำแนะนำ | คลิปใหม่ที่กันไว้และคะแนนจากผู้ประเมินจริง |

## ข้อตกลงสำคัญ

- Prompt ระบุเจตนาและเกณฑ์ตรวจรับ ไม่ได้รับประกันว่าโมเดลสองตัวจะตัดสินใจเหมือนกันทุกจุด ต้องตรวจผลด้วย Test และรายงานจริง
- ค่าตัด จำนวนตัวอย่าง และช่วงเวลาที่เสนอใน Phase 5/7 เป็น **ค่าเริ่มต้นของโครงการ** ไม่ใช่มาตรฐานวิจัยที่พิสูจน์ว่าจำนวนนี้เพียงพอเสมอ ต้องบันทึกก่อนดูผล ห้ามลดเกณฑ์เพียงเพื่อให้ผลดูดี
- Phase 5 เก็บได้ทั้งผลสูงกว่า ต่ำกว่า และยังสรุปไม่ได้ ไม่ใช่ระบบหาเฉพาะตัวเลขที่สนับสนุนคำแนะนำ
- Phase 6 ตรวจสิ่งที่พบในข้อความ ไม่อ้างว่าตรวจคุณภาพเนื้อหาได้เทียบเท่ามนุษย์ และไม่ถือว่าพบหัวข้อแล้วแปลว่าทำตามแผนครบ
- Phase 7 แยก "เครื่องมือประเมินพร้อม" ออกจาก "ประเมินด้วยคนและคลิปใหม่ครบแล้ว" หากยังไม่มีข้อมูล ต้องรายงานว่ายังค้าง
- ไม่เพิ่มค่าใช้จ่าย API, โมเดลสร้างข้อความ, การฝึก/Activate โมเดล หรือการดึงข้อมูลอัตโนมัติโดยพลการ
- โค้ด Phase 4 ใน working tree อาจยังไม่ได้ Commit ห้าม Reset หรือทิ้งงานเดิมเพื่อเริ่ม Phase ใหม่

แต่ละ Prompt ระบุไฟล์ที่ควรอ่านก่อน ขอบเขตที่ห้ามขยาย วิธีคำนวณ สถานะข้อมูลไม่พอ และกรณีทดสอบ เพื่อช่วยลดการตีความเองระหว่างลงมือทำ
