# Phase 2: หลักฐานคำแนะนำและการอนุมัติรวม

## หน้า Dataset Review

- ปุ่ม **อนุมัติทั้งหมด** เตรียมเฉพาะรายการ Pending ที่ตรงกับหมวดและคำค้นปัจจุบัน ครอบคลุมทุกหน้า ไม่ใช่เฉพาะ 12 รายการบนจอ
- หน้ายืนยันแสดงจำนวน รายชื่อ และหมวดที่เสนอ Admin ต้องเลือกคุณภาพ Transcript และยืนยันว่าตรวจ Transcript/หมวดแล้วก่อนอนุมัติ
- ถ้าต้องแก้หมวดของบางรายการ ให้ตรวจรายการนั้นแยกก่อน ใช้ปุ่มรวมเมื่อทุกหมวดที่เสนอถูกต้อง
- ส่งคำขอทีละรายการ มีความคืบหน้า หยุดหลังคำขอปัจจุบันได้ และแยกจำนวนสำเร็จ/ล้มเหลว/ยังไม่ได้ดำเนินการ
- เซิร์ฟเวอร์ตรวจ SHA-256 ของ Candidate และตรวจว่ายังไม่ถูก Review ภายใต้ transaction lock ถ้าอีกคน Review ไปแล้ว จะไม่เขียนทับ
- นับสำเร็จเมื่อได้รับทั้ง Dataset ID และ Review Event ID ที่ตรงกับรายการนั้น ถ้าเครือข่ายขาดหลังเซิร์ฟเวอร์บันทึกแล้ว หน้าจออาจยังยืนยันไม่ได้ ให้โหลดคิวใหม่ก่อนทำซ้ำ
- ปิดเว็บจะหยุดส่งรายการถัดไป แต่คำขอที่ส่งแล้วอาจบันทึกเสร็จ จึงต้องตรวจคิวอีกครั้ง ไม่มีการ Train หรือ Activate Model อัตโนมัติ

โค้ดหลัก:

- `frontend_flutter/lib/widgets/dataset_bulk_approval.dart`: เตรียมคิว ยืนยัน ส่งทีละรายการ และสรุปผล
- `app/routes/dataset_review.py`: endpoint เดิมที่ตรวจสิทธิ์ Admin
- `app/services/youtube_cc_dataset.py::review_youtube_cc_candidate`: ตรวจ Hash/สถานะ บันทึก Dataset และ Review Event

## หลักฐานที่บันทึก

ผลใหม่มี `recommendation.evidence_bundle` เวอร์ชัน `recommendation-evidence-v1` บันทึกรวมกับผลใน `analysis_results.summary` ซึ่งรองรับ LONGTEXT บน MySQL ไม่ต้องเพิ่มตารางซ้ำซ้อน

1. `input`: Raw/Cleaned Transcript, Hash, แหล่งข้อความ, สถานะความสมบูรณ์, Segment ที่มีเวลาจริง, ผลจำแนก และค่าการวิเคราะห์ที่ใช้
2. `topics`: รหัสหัวข้อคงที่ตามหมวดและคำมาตรฐาน คำพ้อง สถานะของคลิปผู้ใช้ทั้งคลิป/ช่วงเปิด และข้อความที่ตรวจพบ
3. `reference_documents`: สำเนาข้อมูลอ้างอิง ณ ตอนวิเคราะห์ ได้แก่ Dataset/Video/Channel IDs, URL, Transcript และ Hash, Split, เวอร์ชัน Dataset, สถิติ, วันเผยแพร่/เก็บสถิติ และที่มาของการ Review
4. `references`: แต่ละหัวข้อเชื่อม Dataset IDs ความถี่ และข้อความต้นทางตัวอย่างสูงสุด 3 ช่วงต่อคลิป เก็บรายชื่อคลิปสนับสนุนทั้งหมด ไม่ตัดเหลือเฉพาะ 3 คลิปที่เคยแสดงเป็นตัวอย่าง
5. `recommendations`: เชื่อมคำแนะนำกับ Topic ID และเหตุผลที่เลือก ไม่มีข้ออ้างเชิงเหตุและผลว่าจะทำให้ Engagement เพิ่ม
6. `duration`: วิธี Median/Percentile ผลคำนวณและ Dataset IDs ที่ใช้
7. `current_trend_ideas`: แยกหลักฐานชื่อคลิป/คำค้น/Snapshot ออกจาก Transcript ไม่ถือว่าชื่อคลิปเป็นสิ่งที่พูดในวิดีโอ
8. `method_version`, `synonym_version`, `data_fingerprint`: เวอร์ชันวิธีจับ Hash ของชุดคำพ้อง และ Hash ข้อมูลประกอบผล

ข้อความอ้างอิงมีตำแหน่งเริ่ม/จบในข้อความต้นทาง (Unicode code points ของ Python) ตรวจย้อนด้วยการตัดช่วงข้อความได้ การแก้ Dataset หรืออัปเดตสถิติภายหลังไม่เปลี่ยนสำเนาหลักฐานของผลเก่า

## สถานะสามแบบ

| สถานะ | ความหมาย |
| --- | --- |
| `detected` | มีข้อความตรงกับคำหรือคำพ้องที่ระบบตรวจจริง |
| `not_detected` | มีข้อความสำหรับตรวจ แต่ไม่พบหัวข้อนั้น ไม่ได้ยืนยันว่าในวิดีโอจริงไม่มีเรื่องนั้นเลย |
| `unassessable` | ถอดเสียงไม่สำเร็จ ข้อความไม่ครบ หรือช่วงเปิดไม่มีเวลาที่ตรวจสอบได้ |

ข้อความบางส่วนอาจพิสูจน์ว่าพบคำหนึ่งได้ แต่ใช้พิสูจน์ว่าไม่พูดคำอื่นไม่ได้ กรณีนี้งดคำแนะนำเพิ่มหัวข้อ ไม่ถือว่าเป็นช่องว่างของเนื้อหา และยังเคารพการตรวจรับหมวดจาก Active Model เดิม

Timestamp มีเฉพาะ Segment ที่มี `start/end` จริงและผูกกับข้อความต้นฉบับได้ เป็นเวลาระดับช่วงเสียง ไม่ใช่เวลารายคำ หาก Segment คร่อมขอบเขต Hook จะไม่เดาว่าคำนั้นอยู่ด้านใด ข้อมูล NotebookLM ที่ไม่มีเวลาไม่ใช้ค่า 0 หรือความยาววิดีโอมาสร้าง Timestamp

คำแนะนำช่วงเปิดในรุ่นนี้มาจากหัวข้อที่ยังไม่ตรวจพบทั้งคลิปและมีหลักฐานจากคลิปอ้างอิง ไม่ได้อ้างว่าคลิปต้นแบบพูดคำนั้นในช่วงเปิดหรือทำให้ Hook มีประสิทธิภาพขึ้นแน่นอน

## การแสดงผลและข้อจำกัด

- เปิดดูแต่ละหัวข้อในส่วน **3. เพราะอะไรจึงแนะนำ** ไม่เพิ่มการ์ด Recommendation Evidence แบบเดิม
- แสดงข้อความต้นทาง จำนวนคลิป/ช่อง สถิติและเวลาที่เก็บ รวมทั้งเปิด URL ต้นทางได้
- ค่าไม่มีข้อมูลไม่แทนด้วยเลขศูนย์ หลักฐานของผลเก่าที่ไม่มี Bundle จะไม่ถูกสร้างย้อนหลังจาก Dataset ปัจจุบันอย่างเงียบ ๆ
- ถ้าผลรุ่นเก่าไม่มี Recommendation บันทึกเลย ระบบเดิมจะคำนวณใหม่เมื่อเปิดดู กรณีนี้ติดสถานะ `recomputed_legacy_not_original` และแจ้งบนหน้าจอว่าไม่ใช่หลักฐานจากวันวิเคราะห์เดิม ไม่เขียนทับผลเก่า
- Phone ใช้ชุดคำพ้องมาตรฐานเดิม ส่วน Camera/Laptop ยังมีหัวข้อแบบคำจากข้อความตามตัวสกัดเดิม Bundle ระบุ `surface_terms_only` ไม่อ้างว่ารวมคำพ้องได้ครบทุกหมวด
- ยังใช้ตัวเลือกคลิปอ้างอิงและการกัน Validation/Test เดิม ไม่ได้นำชุดทดสอบเข้ามาสร้างคำแนะนำ และไม่นับ Video ID เดียวกันเป็นหลายคลิป
- นี่เป็นการทำหลักฐานให้ตรวจสอบได้ ไม่ใช่ผลทดลองว่าคำแนะนำเพิ่มยอดวิวจริง และไม่ได้ปลดเกณฑ์ Unknown ของ Active Model

## การตรวจสอบ

- `tests/test_recommendation_evidence.py`: ข้อความ/ตำแหน่ง เวลา Alias นับซ้ำ สถานะถอดเสียง การกัน Holdout การแยก Trend และการอ่านหลักฐานเดิมหลังแก้ Dataset/เปิด Session ใหม่
- `tests/test_notebooklm_batch.py`: Hash เก่า Review ซ้ำ การไม่เขียนทับรายการ Reject และคิวหายหลังอนุมัติสำเร็จ ใน SQLite ทดสอบ
- `frontend_flutter/test/dataset_bulk_approval_test.dart`: ทุกหน้า ยกเลิก ความล้มเหลว คำตอบที่ไม่ยืนยันการบันทึก และหยุดระหว่างทำงาน
- `frontend_flutter/test/recommendation_evidence_test.dart`: สถานะภาษาไทย ข้อความต้นทาง ค่าสถิติที่ไม่มี และไม่มี Timestamp ที่สร้างเอง
- `scripts/browser/verify_recommendation_evidence.cjs`: เปิดหน้าต่างยืนยันจริงแล้วกดยกเลิก ทดสอบหน้าผลด้วย SQLite Fixture ที่แยกจากข้อมูลจริง และตรวจว่าจำนวน Review ไม่เปลี่ยน

ผลใหม่ต้องวิเคราะห์ใหม่จึงมี Bundle นี้ ไม่ควรนำ Screenshot ของ Fixture ไปอ้างเป็นผลวิเคราะห์คลิปจริง
