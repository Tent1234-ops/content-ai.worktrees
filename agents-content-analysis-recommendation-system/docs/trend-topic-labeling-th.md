# คู่มือระบุหัวข้อสำหรับชุดทดสอบเทรนด์

## ตอนนี้ได้อะไรแล้ว

ระบบคัดชื่อคลิปจริง 200 รายการจาก Snapshot แบ่งเป็นสองชุด:

- `development/labels.csv`: 100 รายการ สำหรับทดลองและปรับวิธีจับหัวข้อ
- `test/labels.csv`: 100 รายการ สำหรับวัดผลหลังหยุดปรับวิธีแล้ว

ทั้งสองชุดไม่มี Video ID ซ้ำกัน และตัดชื่อคลิปซ้ำรวมถึงชื่อเก่าของคลิปเดียวกัน
ออกก่อนแบ่งชุด ข้อมูลชุดนี้ใช้ตรวจการจับหัวข้อ ไม่ใช่ข้อมูลฝึกจำแนก
Phone/Camera/Laptop และยังไม่ใช่ผลว่าระบบแม่นกี่เปอร์เซ็นต์

## ให้คนทำอะไร

เปิดไฟล์ `development/labels.csv` ด้วยโปรแกรมตารางที่อ่าน UTF-8 ได้
อ่านเฉพาะช่อง `title` แล้วกรอกสี่ช่องหลัก:

| ช่อง | สิ่งที่ต้องกรอก |
|---|---|
| `status` | `labeled`, `no_topic` หรือ `ambiguous` |
| `topics` | รายการชื่อหัวข้อในรูปแบบ JSON เช่น `["สกุชชี้"]` |
| `evidence` | ข้อความจากชื่อคลิปที่สนับสนุนหัวข้อ ตามลำดับเดียวกับ topics |
| `annotator` | ชื่อคนที่ตรวจ |

ช่อง `notes` ใช้จดเหตุผล และต้องกรอกเมื่อเลือก `ambiguous`
ห้ามแก้ `sample_id`, `video_id`, `title` หรือไฟล์ `samples.jsonl`

ตัวอย่างสมมุติ ชื่อคลิปคือ `แกะกล่องสกุชชี้รุ่นใหม่`:

```text
status: labeled
topics: ["สกุชชี้"]
evidence: ["สกุชชี้"]
annotator: ชื่อผู้ตรวจ
```

ตัวอย่างสมมุติ ชื่อคลิปคือ `ลองบีบ Squishy รุ่นใหม่`:

```text
status: labeled
topics: ["สกุชชี้"]
evidence: ["Squishy"]
annotator: ชื่อผู้ตรวจ
```

ชื่อหัวข้อใช้ชื่อมาตรฐานได้ แต่ evidence ต้องคัดข้อความที่อยู่ใน title จริง
หนึ่งคลิปมีหลายหัวข้อได้ ใส่เป็น `["หัวข้อหนึ่ง", "หัวข้อสอง"]`
และใส่ evidence ให้ครบในลำดับเดียวกัน ไม่ใส่คำทั่วไปอย่าง รีวิว คลิป วันนี้
เป็นหัวข้อ และไม่ใช้ชื่อหมวดใหญ่แทนชื่อสิ่งที่พูดถึงโดยอัตโนมัติ

## สถานะต่างกันอย่างไร

- `pending`: ยังไม่มีคนตรวจ ไม่ถือว่าเป็นคำตอบเฉลย
- `labeled`: อ่านชื่อแล้วมีหลักฐานพอจะระบุหัวข้อ ต้องมี topics และ evidence
- `no_topic`: ตรวจแล้วชื่อไม่ได้ระบุหัวข้อชัดเจน ใช้ topics/evidence เป็น `[]`
- `ambiguous`: ชื่อมีความหมายกำกวม ตัดสินไม่ได้ ใช้ `[]` และเขียนเหตุผลใน notes

เช่น ชื่อ `ไม่คิดว่าจะเจอสิ่งนี้!` ไม่ควรเดาว่าเป็นของเล่นจากภาพปก
ห้ามดูคลิป คำอธิบาย หรือค้นเว็บเพื่อเติมหัวข้อที่ไม่ได้อยู่ในชื่อ
เพราะสิ่งที่กำลังทดสอบคือการจับหัวข้อจากชื่อเท่านั้น

อย่าให้ AI เติมหัวข้อแล้วนับเป็นคำตอบจากคนทันที จุดประสงค์ของไฟล์นี้คือมี
หลักฐานอิสระไว้ตรวจ AI อีกที โดยเฉพาะชุด test ควรให้คนอีกคนช่วยตรวจหากทำได้

## ใช้สองชุดอย่างไร

1. ตรวจ development ก่อน ใช้ตกลงชื่อมาตรฐานและปรับวิธีจับหัวข้อ
2. เก็บ test ไว้ ไม่ใช้ชื่อหรือคำตอบของ test ไปเพิ่มกฎและคำพ้อง
3. เมื่อหยุดปรับวิธีแล้ว ให้คนระบุหัวข้อของ test และรันประเมิน
4. รายงานทั้งจำนวนที่จับถูก จำนวนที่พลาด และจำนวนที่ระบบไม่มั่นใจ

ไฟล์ `heldout_video_ids.json` ใช้กัน Video ID ของ test ออกจากการพัฒนาใน Phase
ถัดไป ส่วน `observations.jsonl` เป็นหลักฐานสำหรับตรวจข้อมูลทั้งหมด ไม่ใช่ไฟล์
สำหรับให้ระบบเรียนรู้ เพราะมีข้อมูลของ test รวมอยู่ด้วย

## ตรวจไฟล์หลังกรอก

รันจากโฟลเดอร์โปรเจกต์ โดยแทน `BUNDLE_PATH` ด้วยโฟลเดอร์ชุดข้อมูลที่ได้รับ:

```powershell
python scripts/prepare_trend_topics.py validate --bundle BUNDLE_PATH
python scripts/prepare_trend_topics.py validate --bundle BUNDLE_PATH --require-complete
```

คำสั่งแรกตรวจไฟล์ซ้ำ แถวหาย ชื่อถูกแก้ รูปแบบ JSON และข้อความหลักฐาน
คำสั่งที่สองจะไม่ผ่านหากยังมี pending อยู่ แต่การผ่านตัวตรวจไฟล์ไม่ได้แปลว่า
หัวข้อที่คนกรอกถูกทางความหมายทั้งหมด ยังต้องตรวจเนื้อหากันเอง

ไฟล์นี้ไม่จำเป็นต้องเปิดหน้าเว็บ และยังไม่มีหน้าจอ Admin สำหรับกรอกหัวข้อ
ใน Phase 1 หากโปรแกรมตารางแก้รูปแบบ CSV จนตรวจไม่ผ่าน อย่าแก้ไฟล์ต้นฉบับ
ใน samples.jsonl ให้ใช้ข้อความผิดพลาดจากตัวตรวจเพื่อแก้เฉพาะ labels.csv
