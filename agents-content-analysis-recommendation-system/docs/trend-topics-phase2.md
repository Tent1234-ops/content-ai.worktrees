# Phase 2: Title Topic Extraction

## Files And Commands

The frozen Phase 1 bundle now lives in
`artifacts/trend-topics/evaluation/phase1-20260925/`.
Its file contents, sample allocation and label CSVs are unchanged.
All new discovery runs go to `artifacts/trend-topics/runs/<timestamp>/`.

```powershell
python scripts/discover_trend_topics.py --bundle artifacts/trend-topics/evaluation/phase1-20260925 --source discovery
python scripts/discover_trend_topics.py --bundle artifacts/trend-topics/evaluation/phase1-20260925 --source development
python scripts/prepare_trend_topics.py validate --bundle artifacts/trend-topics/evaluation/phase1-20260925
```

`development` uses only the 100 development examples. `discovery` reads the frozen
audit corpus and excludes all held-out Video IDs and copies of any held-out title
variant before extraction. Repeated snapshots/category appearances do not become
additional supporting videos. Use no test titles or labels for rule/alias tuning.
Reading opaque held-out hashes for exclusion is allowed, not semantic processing.

The CLI never calls YouTube, changes labels, writes to the database, or downloads
model weights. The default requires the cached multilingual MiniLM model and
KeyBERT. It fails explicitly if the model cannot load. `--semantic off` is an
explicit diagnostic mode; scores are null and no semantic alias suggestions are
produced in that mode. No paid AI API or Codex plugin is needed at runtime.

## Pipeline

1. Validate the frozen bundle and hashes, then filter the holdout BEFORE NLP.
2. Preserve exact original titles. PyThaiNLP newmm tokenizes Thai, with a custom
   dictionary for known multiword names and generic compound stopwords. Latin
   product identifiers stay intact. Offsets always point into the original title.
3. Match catalog aliases using word boundaries and local context where required.
   Squishy in a software or recipe context does not become the toy. The two
   initial known topics come from explicit project examples, not mined test labels.
4. Generate contiguous 1-5 token phrases and hashtags. Remove generic words and
   avoid phrases that bridge comparison/conjunction/action boundaries. No topic
   names are generated by an LLM or inferred from descriptions/categories/views.
5. Count distinct supporting Video IDs and nonempty normalized channel titles.
   Defaults: at least 3 videos and 2 channel titles, with at most 2000 supported
   phrases sent to the semantic ranker. These are heuristics, not significance tests.
6. Use KeyBERT with a candidate-aware CountVectorizer. The vectorizer only exposes
   phrases actually present in each title, including unspaced Thai. Encode titles
   and candidate phrases using the cached multilingual MiniLM model on CPU.
7. Rank proposals by mean semantic similarity over supporting titles; default
   minimum is 0.30. Record the thresholds, model revision and input/catalog hashes.
   Similarity is NOT classification confidence, trend strength or viral probability.
8. Propose similar name pairs for human review only. Semantic similarity alone
   is related_only; different model numbers are different_product_variant; even
   a possible_alias is never merged automatically. Catalog never_merge pairs
   remain separate.
9. Return matched_known, needs_review, or unknown per video. Unknown means there
   is insufficient evidence under these rules, not that the video has no topic.

## Outputs

- `summary.md`: readable Thai summary and links to the other outputs.
- `documents.jsonl`: original title, verified video link, known matches, exact
  evidence spans, original observation/run reference, candidates and abstentions.
- `candidates.csv`: human-readable proposal queue; NOT a gold-label input.
- `candidates.jsonl`: all proposed names and their supporting clips/title excerpts.
- `alias_suggestions.json`: similar-name pairs with reasons and review-only status.
- `run.json`: model/catalog/library versions, pipeline code hashes, thresholds, corpus exclusions,
  hashes, limitations and `accuracy: null` until an independent evaluation exists.

Each run uses a new directory and refuses to overwrite existing results or write
inside the frozen bundle. Phase 3 will persist topic decisions/history; Phase 4
adds charts; Phase 5 adds Admin review controls. This phase does not expose
unreviewed labels as public trends or alter the existing AI Analyze classifier.

## Limitations

New proposals may still be generic phrases or separate fragments of the same
name. Review is necessary, especially for previously unseen Thai names. The
3-video/2-channel rule can miss a new topic present in only one popular clip.
Channel names are only proxies because snapshots do not contain stable channel
IDs. Support is across the selected corpus, NOT the current Top 50 or growth.
Multilingual embeddings are not an entity-identity oracle. Title-only evidence
cannot prove what is discussed throughout a video, and model text truncation may
affect long-title similarity scores. Human Phase 1 labels are still pending.

## Checks

```powershell
python -m unittest tests.test_trend_topics tests.test_trend_topic_preparation tests.test_trend_history -q
```

Tests cover Thai aliases, contextual English aliases, unknown titles, product
phrases, exact spans, novel names absent from the catalog, cross-snapshot/video
deduplication, minimum independent support, safe semantic-disabled behavior,
review-only alias suggestions, holdout exclusion and unchanged gold labels.
